# 容量估算練習包（Windows 11，只需要 g++）

這個練習包把[研究報告](../beyond-dsa.zh-TW.md)第 3.3 節「容量估算」的原則做成刻意練習：先寫假設、數字一定標單位、讀寫分開、尖峰取平均的 2 到 3 倍、用整數、對數量級。

- **42 題原創的單題練習**，加上 **3 條串連練習**（每條 5 步）。題目和數字是為這個專案寫的練習假設，不是任何公司的真實數據，也不是從題庫或解答抄來的。
- **`est` 練習工具**：一個 C++ 檔案，跟 [cpp-practice](../cpp-practice/README.zh-TW.md) 的 `pp`、[ai-round-practice](../ai-round-practice/README.zh-TW.md) 的 `drill` 同一套做法。訊息是繁體中文。
- **只需要 WinLibs GCC。** VS Code 可用可不用：有的話，工作（tasks）已經設定好；沒有的話，在終端機直接執行 `est`。

## 1. 先讀這段：練習包怎麼幫你

| # | 報告的原則（第 3.2、3.3 節） | 練習包怎麼做 |
| --- | --- | --- |
| 1 | **寫下假設** | 每題作答前，要先寫至少一行含數字的假設；沒寫就不能作答。假設會存進 `progress/journal.md`。 |
| 2 | **數字要標單位** | 答案沒有單位、單位寫錯種類（例如問頻寬卻寫 GB）、或大小寫分不出位元和位元組（`1.2 tb`），都會被退回並說明原因。退回次數會記錄下來。 |
| 3 | **不追求精確，對數量級** | 跟參考答案的比值在 3 倍內就算命中（要自己假設關鍵大小的題目放寬到 10 倍）。理由見第 4 節。 |
| 4 | **讀和寫的 QPS 分開算** | 很多題同時問讀和寫，或請求數和紀錄數，而且故意讓其中一邊比較大。 |
| 5 | **尖峰約是平均的 2 到 3 倍** | 有些題目給流量分布、要你算尖峰；有些題目要你自己選倍數並說明理由。 |
| 6 | **估算要接到設計決策** | 每題的參考答案最後都有「對設計的意義」：要不要分片、放不放得進記憶體、要不要 CDN。 |
| 7 | **容量估算 0 到 5 分鐘** | 每題限時 5 分鐘。超時但答對，記為 `slow`，複習間隔減半。 |
| 8 | **先自己做，再對照**（第 3.6 節） | 參考推導在作答後才顯示。題庫檔在 VS Code 裡預設隱藏。 |
| 9 | **說出卡在哪**（第 3.6 節的複盤卡） | 看完推導後，要指出從哪一步開始偏離、寫一句原因，才會記錄。沒寫就不記錄。 |
| 10 | **照框架把數字串起來**（第 3.2 節） | 串連練習：使用者 → QPS → 儲存 → 頻寬 → 伺服器，一步一步算完一個系統。 |
| 11 | **交錯與間隔複習**（[刷題報告](../dsa-practice.zh-TW.md)的方法） | 不指定題目時，先排到期的題目，再排新題，而且不會連續兩題同一種題型。沒命中的題目隔天再出現。 |
| 12 | **找出系統性偏差** | `est stats` 依題型算 log 比值的平均，告訴你是系統性高估、低估，還是只是誤差大。 |

## 2. 安裝與建置

1. 安裝 WinLibs GCC。已經為 cpp-practice 或 ai-round-practice 裝過就跳過。

   ```bash
   winget install --id BrechtSanders.WinLibs.POSIX.UCRT --exact
   ```

2. **用 VS Code：** 用「檔案 → 開啟資料夾」打開 `estimation-practice`。第一次執行任何 `est:` 工作時，會自動建置 `build/est.exe`（約 10 秒）。
3. **不用 VS Code：** 在 `estimation-practice` 資料夾執行：

   ```bash
   g++ -std=c++20 -O2 -static -o build/est.exe tools/est.cpp
   build\est.exe --self-test
   ```

## 3. 一次練習的流程

| 要做的事 | VS Code 工作 | 終端機 |
| --- | --- | --- |
| 看今天該做什麼 | `est: 今日練習` | `est today` |
| 交錯練 3 題（約 15 分鐘） | `est: 交錯練習 3 題`（Ctrl+Shift+B） | `est drill` |
| 練指定的題目或題型 | `est: 練指定的題目或題型` | `est drill shortlink-qps`、`est drill bandwidth` |
| 到期複習 | `est: 到期複習` | `est review` |
| 串連練習（約 15 分鐘） | `est: 串連練習` | `est chain`、`est chain photo-app` |
| 看偏差 | `est: 偏差統計` | `est stats` |
| 題庫與狀態 | `est: 題庫清單` | `est list` |
| 只看會選到哪幾題 | | `est drill -n 5 --plan` |

工作開始後，直接在下方終端機面板輸入。每題的步驟：

1. **讀題。** 題目會列出已知條件和要估的量，例如「尖峰讀取 QPS（速率；容許 3 倍）」。時鐘開始。
2. **寫假設。** 一行一個，空白行結束。例如 `一天約 10^5 秒`、`尖峰 = 平均 × 3`、`每筆 500 B`。
3. **作答。** 每個量寫數字加單位，例如 `15k QPS`。被退回就照提示重寫。
4. **看結果和參考推導。** 每個答案會顯示比值與 log10(你的 / 參考)，接著是參考的假設、編號的推導步驟，以及對設計的意義。
5. **指出偏離的地方。** 輸入推導的步驟編號（0 表示假設本身就不同），再寫一句原因。沒命中或超時時，原因是必填的；都命中時可以輸入 `-` 跳過。
6. **記錄並排下次複習。** 命中：3 → 7 → 14 → 30 → 60 天；超時：間隔減半；沒命中：明天。命中且間隔到 60 天以上，就不再出現在到期清單。

**串連練習**先寫整條鏈的共同假設，然後一步一步作答。每一步作答後立刻揭曉參考答案，下一步用參考答案繼續，所以每一步只量那一步的估算，一步錯不會拖累後面。最後指出從哪一步開始偏離，再指出那一步推導裡的哪一行。

## 4. 計分規則與理由

**命中的定義：** |log10(你的答案 / 參考答案)| ≤ log10(容許倍數)。

| 容許 | 用在哪裡 | 理由 |
| --- | --- | --- |
| **3 倍**（約半個數量級，log10 ≈ 0.48） | 題目給了所有關鍵數字的題目（63 個提問，加上串連的 16 個） | 這時合理的差異只來自取整：一天用 10⁵ 秒還是 86,400 秒（差 16%）、尖峰取 2 倍還是 3 倍（差 1.5 倍）、中間值取 1 到 2 位有效數字。參考答案和精確計算最多差 1.25 倍（見第 9 節）。超過 3 倍通常是結構性的錯：漏了一個因子（副本、保存年限、扇出）、位元和位元組（8 倍）、一天的秒數（10⁴ 和 10⁵）。3 倍也剛好大到會改變設計決策：一台還是三台、放不放得進一台機器的記憶體。 |
| **10 倍**（一個數量級） | 題目要你自己假設關鍵大小的題目（目前 2 題：`shortlink-storage`、`shortlink-cache`，題目會寫明） | 合理的假設本身就差好幾倍，例如每筆紀錄 200 B 或 2 KB。第 3.3 節的原則是對數量級，結論（幾台機器、放不放得進記憶體）在這個範圍內不變。 |

- **單位必填。** 單位缺了或種類不對，答案不會被評分，而是退回重寫。
- **先寫假設。** 至少一行含數字，才能作答。
- **限時 5 分鐘**（第 3.2 節：容量估算 0 到 5 分）。`--minutes` 可以調整，串連練習每步預設 3 分鐘。
- **偏差用 log 比值算。** 高估 2 倍和低估 2 倍的 log 值大小相同、方向相反，平均起來會互相抵消；而且不會被大數字主導。`est stats` 的判讀：做滿 3 次才判讀；平均 |log| < 0.15（約 1.4 倍）算沒有明顯偏差；平均超過這個值、而且至少 2/3 的答案在同一方向，就是系統性高估或低估。

## 5. 作答的寫法

| 種類 | 可以寫 | 會被退回 |
| --- | --- | --- |
| 數字 | `3e5`、`300k`、`2.5M`、`1.5bn`、`86,400`、`2^30`、`3×10^5`、`2000萬`、`1.5億`、`2千萬`；前面可以加 `~`、`≈`、`約` | `300k`（沒單位）、`3,00`（千分位寫錯） |
| 速率 | `15k QPS`、`200 /s`、`3k req/s`、`5億 次/天`、`12 req/min`、`3k 次每秒` | `3000 requests`（沒有「每秒」）、`40 MB/kg` |
| 資料量 | `1.2 TB`、`500 GB`、`64 KiB`、`8 Tb`（位元，會換算成 1 TB） | `1.2 tb`、`3 gb`（分不出位元組或位元）、`40 mB`（小寫 m 是「毫」） |
| 頻寬 | `40 MB/s`、`320 Mbps`、`10 Gb/s`、`2 TB/day` | `40 mb/s`、`13.5 GB`（問頻寬卻寫總量） |
| 時間 | `500 µs`、`500 us`、`150 ms`、`2.5 s`、`22 min`、`1.8 h`、`3 天` | `5m`（分鐘請寫 min） |
| 數量 | `43 台`、`200 個分片`、`200 partitions`、`34 GPU servers`、`1億 人`、`2.5M users` | `2.5B users`（B 是位元組，十億請寫 1bn 或 10億） |

前綴是十進位（1 KB = 1,000 B），跟報告第 3.3 節「2¹⁰ ≈ 一千」的估算習慣一致；KiB、MiB 是二進位。`est parse <文字>` 可以先試試某個寫法會怎麼被解析。

## 8. 放進 12 週計畫

報告第 7.2 節的「系統設計」欄在第 1–2 週安排了讀估算（第 3.3 節）。練習包的建議排法如下，時間從第 7.1 節系統設計每週約 7 小時裡撥出，每週約 30 到 45 分鐘：

| 週 | 練習 |
| --- | --- |
| 1–2 | 讀完第 3.3 節後，每週 2 次 `est drill`（每次 3 題、約 15 分鐘），先把 7 種題型都碰過 |
| 3–8 | 每次做系統設計完整練習之前，先跑 `est review`（到期的題目，5 到 10 分鐘）；每週 1 次 `est chain` |
| 9–12 | 只做 `est review` 和串連；模擬面試前一天看 `est stats`，確認沒有系統性偏差 |

**準備好了的標準**（本練習包的建議，不是報告第 7.4 節的一部分）：每種題型至少做過 3 次、命中率 80% 以上；`est stats` 沒有任何題型被判為系統性偏差；串連練習能在 15 分鐘內做完、沒有沒命中的步驟。

題目重做時你可能記得答案。所以複習時重點不是數字，而是能不能在 5 分鐘內、不看推導，重新寫出假設和推導；面試時面試官也會改條件（第 3.6 節的變體練習），例如「寫入量變 10 倍」，你要能從推導裡改那一步。

## 9. 已驗證

以下都是在 Windows 11、WinLibs g++ 16.2.0、Python 3.14 上實際跑過的。

- **單位解析測試：** `est --self-test` 89 個案例全部通過，包括 63 個可接受的寫法、15 個要退回的寫法、6 個單位種類不符的情況、5 個格式化輸出。
- **題庫檢查：** `est --self-test` 也檢查 42 題單題和 3 條串連（15 步）：每個提問都有參考答案、參考答案的單位種類正確、推導步驟的類型都認得、串連步驟依序編號。
- **參考答案用另一種方法重算：** `tools/verify_bank.py`（只用 Python 標準函式庫，跟 `est.cpp` 不共用程式碼）有自己的單位解析器和題庫讀取器，對**全部 81 個提問**（42 題單題的 65 個、串連 15 步的 16 個）從已知條件用精確值（一天 86,400 秒、一年 365 天）重新計算。參考答案和精確值的差距都在 1.35 倍以內，最大是 1.25 倍（`video-upload` 的上傳頻寬：參考 100 Gbps，精確值 125 Gbps）。它也確認每個參考答案的文字出現在推導裡，串連每一步引用的上一步答案跟上一步的參考答案一致。
- **兩個解析器互相核對：** 題庫裡全部 279 個已知條件和答案（加上 22 個額外寫法），`est` 和 Python 解析出的單位種類和數值都一致；8 個錯誤寫法兩邊都退回。
- **完整流程跑過**（用管線餵入輸入，進度寫到暫存資料夾）：答對（記為 hit，3 天後複習）；缺單位、單位種類不對、大小寫不明各被退回一次，接著 8 倍的位元與位元組錯誤（記為 miss，隔天複習）；串連 `photo-app` 五步（第 4 步故意少乘 10，記為 miss）；沒寫假設時不能作答；沒命中卻沒寫原因時不記錄、以非 0 結束；超時但答對（記為 slow）；`est stats` 的偏差報表；用 `EST_TODAY` 把日期設成隔天，`est today` 列出到期的題目，`est review` 答對後間隔變成 3 天；`est drill --plan` 的交錯選題前 7 題涵蓋 7 種題型。大部分在 Git Bash 用管線輸入；另外在 Windows PowerShell 5.1（`$OutputEncoding` 為 UTF-8）用管線輸入中文假設做完一題，紀錄裡的中文正確。
- **VS Code 工作的建置指令：** 刪掉 `build/est.exe` 後，用 `cmd.exe` 執行「est: 確認工具已建置」那一行指令，會重新建置出 `est.exe`。

**沒有驗證的：**

- 在 VS Code 的終端機面板裡互動輸入。工具在 Windows 主控台用 `ReadConsoleW` 讀取，讓中文輸入不受字碼頁影響，但這次只用管線測試過，沒有在真正的主控台或 VS Code 工作裡打字測試。
- Linux 和 macOS：程式碼有處理，但沒有實際編譯測試。
- 題目裡的情境數字（使用者數、每筆大小、單機容量）是練習假設，沒有對照任何真實系統。

## 10. 新增題目

題庫在 `drills/*.txt`，UTF-8 純文字。VS Code 預設隱藏這個資料夾；要編輯時把 `.vscode/settings.json` 裡的 `"drills"` 暫時改成 `false`。

```
== drill <id>
title: 題目名稱
kind: 對應第 3.5 節的題目
type: storage                         （選填：歸到哪個題型；預設是第一個提問的題型）
scenario: 情境說明（可以有多行 scenario:）
given: key = 數量 | 說明               （作答前顯示）
ask: key | 題型 | 單位種類 | 說明 [| 容許倍數]
answer: key = 數量                     （參考答案，用整數）
assume: 參考答案的假設
calc: 步驟類型 | 推導的一步             （必須有一行包含參考答案的原文）
design: 這個數字對設計的意義
```

- 題型：`users`、`qps`、`storage`、`bandwidth`、`memory`、`servers`、`fanout`、`time`。
- 單位種類：`count`、`rate`、`bytes`、`byterate`、`time`。
- 步驟類型（`est stats` 用來統計你常在哪類步驟偏離）：`assume`（假設）、`unit`（單位或時間換算）、`peak`（尖峰倍數）、`mix`（讀寫比或比例）、`size`（單筆大小）、`mult`（乘上數量或時間）、`copy`（副本、索引與額外負擔）、`cap`（單機容量與餘裕）、`fan`（扇出倍數）。
- 串連用 `== chain <id>` 寫共同情境，每一步用 `== step <chain-id> <n>`。

改完後執行 `est --self-test`。如果有 Python，再到 `tools/verify_bank.py` 的 `FORMULAS` 加上這題的公式，執行：

```bash
python tools/verify_bank.py --exe build/est.exe
```

練習者不需要 Python，這個腳本只給維護題庫的人用。

## 11. 專案結構

```
estimation-practice/
├─ .vscode/               工作設定；隱藏 drills/（有參考答案）、build/、progress/
├─ tools/
│  ├─ est.cpp             練習工具（第一次執行工作時自動編譯）
│  └─ verify_bank.py      維護者用：用另一種方法重算每個參考答案、核對兩個解析器
├─ drills/                題庫：10-qps、20-storage、30-bandwidth、40-memory、50-servers、
│                          60-fanout、70-time、90-chains
├─ progress/              你的紀錄（自動建立，不進版本控制）
│  ├─ attempts.tsv        每個提問的答案、參考、log 比值、偏離的步驟
│  ├─ reviews.tsv         每次練習的結果與下次複習日
│  └─ journal.md          你寫的假設和偏離原因
└─ build/                 建置產物（隨時可以整個刪掉）
```

## 12. 疑難排解

| 症狀 | 處理 |
| --- | --- |
| 找不到 `g++` | 裝完 WinLibs 後要重開終端機或 VS Code。執行 `where g++` 確認。 |
| 中文變亂碼 | 先執行 `chcp 65001`。 |
| 從 PowerShell 用管線餵答案時中文變成問號 | 管線的編碼由 `$OutputEncoding` 決定。把它設成 `[Text.Encoding]::UTF8`，或直接互動輸入。 |
| 想重來 | 刪掉 `progress/` 整個資料夾。 |
| 改了 `tools/est.cpp` | 執行工作「est: 重新建置工具」。 |
| 想把紀錄放在別的地方 | 設定環境變數 `EST_PROGRESS` 指向那個資料夾。 |
