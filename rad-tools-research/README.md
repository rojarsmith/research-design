# RAD tools: development difficulty and resource thresholds

Research date: 2026-10-21. This is an English overview; the full study and supporting documents are in Traditional Chinese.

The primary question is what it takes to **build a Rapid Application Development tool as a product**, across ten domains and three maturity levels. A separate section distinguishes the much smaller effort of using an existing RAD tool to build an application. RAD here includes visual UI construction, model-driven applications and visual workflows; embedded graphics libraries and game engines are adjacent building blocks, not automatically complete RAD products.

The central engineering inference is that a constrained tool built on an existing runtime is a realistic small-team project. A general platform adds execution semantics, deployment, security, project migration, integrations, debugging and a support ecosystem. A working canvas alone provides little evidence of commercial readiness. Public vendor documentation supports capability and architecture claims, **not the staffing or cost estimates**.

For initial planning, this study models a narrow prototype at 1–3 people for 2–4 months, a focused commercial product at 4–8 people for 9–18 months, and a mature platform program at 15–40 people for 24–48+ months. These are scenario assumptions, not industry benchmarks or estimates of any named vendor's investment. Domain-specific ranges and exclusions are in the resource model; the largest full-stack programs can exceed them substantially.
