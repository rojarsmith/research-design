# 03｜ETSI EN 303 645、測試與付費認證層級

研究日期：2026-10-20

## ETSI EN 303 645 是什麼

ETSI [EN 303 645](https://www.etsi.org/deliver/etsi_en/303600_303699/303645/02.01.01_60/en_303645v020101p.pdf) 是消費型 Internet of Things 裝置的網路安全基線，內容包含通用密碼、弱點揭露、軟體更新、儲存敏感安全參數、通訊安全、減少攻擊面、完整性、個人資料保護等。它是標準，不是 ETSI 對某個伺服器／SaaS 實際頒發的「CRA 證書」。其適用對象以消費型 IoT 裝置為主；若單獨測 OTA 平台 SaaS，需先確定測試對象和適用條文。若評估完整 OTA 方案，適合把裝置、雲端、管理介面、API、更新客戶端、供應與營運流程納入明確界定的系統邊界。

ETSI [TS 103 701](https://www.etsi.org/deliver/etsi_ts/103700_103799/103701/02.01.01_60/ts_103701v020101p.pdf) 是 EN 303 645/TS 103 645 的符合性評估方法，提供 ICS/IXIT、測試群組和評估程序。TS 103 701 對評估角色區分自我評估、使用者組織第二方評估與獨立第三方測試實驗室；標準本身不指定所有方案都需第三方，也未建立單一通用證書或統一費率。

## 不能混淆的五種結果

| 結果 | 代表什麼 | 不代表什麼 |
| --- | --- | --- |
| 自我檢查表／自我聲明 | 供應者自行整理控制與差距 | 不代表獨立測試或 CRA 認證 |
| 獨立滲透測試 | 某一範圍／版本接受特定攻擊測試 | 不等同全面 CRA 符合性或 ETSI 證書 |
| 依 TS 103 701 完成的實驗室評估 | 實驗室按測試方法評估界定的 DUT 和範圍 | 不自動代表 CRA 符合性或法定 CE 評估 |
| 自願產品認證／標章 | 依特定 scheme 的認證規則頒證（例如實驗室／認證機構方案） | 不一定涵蓋 CRA 所有要求；核實標章規則、認證範圍、有效期與機構認可 |
| CRA 法定符合性程序 | 製造商依 CRA 類別完成法定程序、技術文件、EU DoC、適用時 CE | 不是由「買一份 EN 303 645 報告」自動得到 |

## ETSI EN 303 645/TS 103 701 要花多少錢？

- **讀取官方標準文件：** ETSI 對公開下載的 EN/TS 文件未向一般使用者收取評估費；取得／閱讀文件與正式測試是兩件事。商業產品使用商標、標準全文再散布及各國採用版本要各自核實授權條款。
- **自己照標準評估：** 沒有 ETSI 發證費，但要投入工程、測試、文件和修復的人力；測試設備或外包專業可能有成本。
- **第三方評估：** ETSI 沒有設定統一公開價格。實驗室要依 DUT、功能、手機 App／雲端 API 範圍、設備數、文件品質、測試樣本、重測及差距修復報價。需拿至少 2–3 份同一範圍報價比較。
- **CRA assessment：** 不是 EN 303 645 的固定價格項目。若產品分類依法要求 Notified Body，另向當時已列入 NANDO 的 CRA 通報機構詢問；確認其通知範圍涵蓋產品類別及評估模組。

可找到的測試商業價目多為特定消費裝置滲透測試，例如 [SafetyBis 公開的 IoT 測試價目](https://www.safetybis.com/pentest/iot-penetration-testing/)列出單一 IoT 裝置基礎測試約 €3,500 起、裝置＋App＋雲端測試約 €5,000–€10,000，複雜裝置約 €10,000–€25,000，另有自願標準映射費。這是單一商家的產品測試價目範例，**不是 OTA SaaS 報價、不是正式 CRA 評估價格、也非市場平均值**。服務邊界、裝置數、灰度部署、客戶租戶隔離、簽章服務、管理後台和雲端弱點測試都可能改變費用。

## 建議的分層保證路線

**Level 0｜可誠實說明的基本衛生（低現金費用）**

- 對客戶清楚標記「managed OTA service」「TLS/HTTPS transport」及免費／入門簽章真正代表的功能。
- 公開 security contact / vulnerability disclosure policy、隱私通知、資料位置、支援期、變更紀錄。
- 產生 SBOM，固定依賴版本，建立漏洞掃描、修補優先順序及上游 hawkBit 安全公告追蹤。
- 建立發布雙人覆核、租戶隔離測試、事故聯絡和備份還原步驟。

**Level 1｜可供採購審核的供應商保障（中等成本，優先推薦）**

- 明確的安全架構／威脅模型和共享責任矩陣。
- 外部應用/API/雲端滲透測試，範圍寫明多租戶隔離、認證與授權、更新流程、儲存／下載、管理面及拒絕服務限制；修補後重測。
- ISO/IEC 27001 對組織 ISMS 的認證可服務企業供應商資格，但不是 CRA 產品認證。是否值得，取決於目標客戶招標門檻和公司是否能持續營運 ISMS。
- DPA、子處理者、備份／災復紀錄與客戶問卷包。

**Level 2｜獨立產品基線評估（較高成本）**

- 針對一組明確 DUT（例如 reference device + OTA backend + management console）由有能力的實驗室依 EN 303 645/TS 103 701 做正式 gap/conformity assessment。
- 或取得由認可機構依可驗證 scheme 發出的產品證書／標章。要看該 scheme 是否涵蓋雲端、更新服務和相應設備；不能只看徽章名稱。
- 出具版本化測試報告摘要，限制宣稱為評估的產品、版本、日期和例外。

**Level 3｜CRA 法定評估（視產品分類，成本高且不一定要買）**

- 先確認產品在 CRA 下的製造商、產品邊界和 Annex III/IV 類別。
- 一般類產品的 Module A 可由製造商自我執行；Class I 路徑取決於符合標準／規格／認證方案的法律狀態；Class II／critical 涉及通報機構或法規允許的認證方案。
- 第三方只能按其 CRA 通知範圍提供法定評估。一般資安顧問、滲透測試商或 ISO 認證機構，不會因有資安專長就自動是 CRA 通報機構。

## 詢價規格（複製給實驗室）

請報兩種範圍：A. 單一 SaaS 平台及管理面；B. reference device + device agent + OTA backend 全端。請列出：

- EN 303 645 版本、TS 103 701 版本、測試項目／例外、受測產品 build 與租戶配置；
- 是否涵蓋 API、web 管理介面、裝置通道、更新客戶端、簽章流程、供應鏈/流程檢視與組織措施；
- 實驗室認可狀態、認可範圍、測試人日、報告樣本、交付成果和報告可否分享客戶；
- 發現缺失後的差距修復支援、免費／付費重測、預約期、保密條款；
- 結果是測試報告、attestation、scheme certificate，還是法定 CRA conformity assessment；證書有效期、監督和變更再評估成本。

以同一範圍詢價可避免把低價單裝置掃描與全端 OTA 產品評估錯誤相比。
