# Hyperliquid 與現代去中心化衍生品交易所

研究日期：2026-11-03（Asia/Taipei）。問題：

1. Hyperliquid 為什麼能做去中心化衍生品交易所？和 2017 年的 EtherDelta 差在哪裡？
2. 這種高吞吐量設計的帳本會不會無限膨脹？他們怎麼處理？

## 結論

- EtherDelta 慢，是因為把交易所塞進以太坊 L1 這台昂貴的全球共用電腦：每次存款、成交、提款都是一筆鏈上交易，要付 ETH gas、等出塊，還會被搶跑。
- Hyperliquid 的解法是**為交易所專門造一條鏈**：訂單簿、撮合、保證金、清算直接寫在鏈的核心邏輯（HyperCore），用 HyperBFT 共識做到不到 1 秒的最終確認；交易用錢包簽名而不是付 gas，加上只能交易、不能提款的 Agent Wallet，體驗接近中心化交易所。
- 代價是信任集中：驗證者數量少，跨鏈橋靠驗證者多簽，而且有過人工干預的紀錄（2025 年 3 月 JELLY 事件）。
- 帳本成長是**線性**而非指數，但斜率很陡。Hyperliquid 把資料拆成兩種處理：**狀態**用訂單短命、掛單上限、速率限制壓在有界範圍；**歷史**移出共識層，節點用快照同步、自行刪除舊資料，完整歷史放在公開的 S3 存檔與第三方索引商。

## 一、EtherDelta 的瓶頸

EtherDelta（2016–2017）的架構：

- **掛單**：鏈下伺服器上的簽名訊息。
- **成交、存款、提款**：呼叫以太坊 L1 智能合約，每個動作都是一筆鏈上交易。

| 問題 | 原因 |
| --- | --- |
| 每個動作都要準備 ETH | 每筆鏈上交易都要付 gas |
| 慢 | 以太坊每 12–15 秒出一個區塊，壅塞時更久 |
| 容易被搶跑 | 成交交易在 mempool 公開，別人可以加價插隊 |
| 跑不起即時撮合 | EVM 每一步運算都要付費 |

核心矛盾：交易所需要毫秒級、高頻、便宜的狀態更新，以太坊 L1 的設計剛好相反。

## 二、業界的四條路線

| 路線 | 代表 | 做法 |
| --- | --- | --- |
| AMM 流動性池 | Uniswap | 不用訂單簿，用公式和資金池交換；解決流動性，但仍在 L1 付 gas |
| L2 Rollup | dYdX v3（StarkEx）、Lighter | 運算搬到鏈下，用零知識證明或詐欺證明保證正確，結果提交回以太坊 |
| 預言機定價池 | GMX（Arbitrum）、Drift（Solana） | 不撮合買賣雙方，以預言機價格和 LP 資金池對賭 |
| 專用應用鏈 | dYdX v4（Cosmos）、Hyperliquid | 為交易所寫一條自己的區塊鏈 |

## 三、Hyperliquid 的做法

### 1. 撮合引擎寫進鏈的核心

撮合不是 EVM 上的智能合約，而是鏈本身的原生邏輯（HyperCore，Rust 實作）。每一筆下單、撤單、成交、清算都經過共識並記錄在鏈上，任何人都能查詢，這點和「鏈下撮合、鏈上結算」的混合式 DEX 不同。

**HyperEVM** 和 HyperCore 共用狀態，讓第三方能部署借貸、金庫等智能合約。

### 2. HyperBFT 共識

- 改良自 HotStuff 系列的 BFT 共識，由驗證者投票出塊。
- 不到 1 秒即最終確認（官方宣稱中位延遲約 0.2 秒），不用像以太坊早期那樣等好幾個區塊。
- 驗證者數量是數十個等級；共識快，部分原因就是用去中心化程度換效能。

### 3. 用簽名取代 gas

- 下單時錢包只簽一個 EIP-712 訊息，**不需要持有 HYPE 或 ETH 當燃料**。
- 防洗單改用交易手續費加**與成交量掛鉤的速率限制**。
- **Agent Wallet／API Wallet**：主錢包授權一把只能交易、不能提款的子金鑰，之後下單不用每次跳出簽名視窗。

### 4. 出入金

- 最早入口是 **Arbitrum 跨鏈橋**：在 Arbitrum 存入 USDC，驗證者確認後入帳；Arbitrum gas 只要零點幾美分。
- 提款由驗證者簽名放行（需 2/3 質押權重），通常幾分鐘到帳，手續費約 1 USDC，直接從 USDC 扣。
- 後來有 Circle 原生 USDC（支援 CCTP），以及 Unit 等協議讓 BTC、ETH、SOL 原生資產直接存入。

### 5. 永續合約機制

| 元素 | 做法 |
| --- | --- |
| 標記價格 | 驗證者定期回報各大 CEX 現貨價格，取加權中位數當預言機價格 |
| 資金費率 | 每小時結算，讓合約價格貼近現貨 |
| 保證金與清算 | 鏈上狀態機即時計算，不足即清算 |
| 流動性 | **HLP 金庫**：社群資金造市並承接清算部位，賺手續費也承擔虧損 |
| 最後防線 | **ADL 自動減倉**：極端行情 HLP 承接不了時，強制減少獲利方部位 |

### 6. 對照 EtherDelta

| | EtherDelta（2017） | Hyperliquid（2026） |
| --- | --- | --- |
| 撮合位置 | 鏈下訂單簿、L1 合約結算 | 自有 L1，撮合寫在共識裡 |
| 成交速度 | 15 秒到數分鐘 | 不到 1 秒 |
| 每筆成本 | ETH gas（壅塞時很貴） | 只有交易手續費 |
| 需要燃料幣 | 要 | 交易時不用 |
| 搶跑風險 | 高 | 共識內排序，較低 |
| 產品 | ERC-20 現貨 | 永續合約、現貨、金庫 |

## 四、去中心化程度

| 面向 | 現況 |
| --- | --- |
| 驗證者 | 數量遠少於以太坊，早期主要由團隊營運，後來逐步開放 |
| 跨鏈橋 | 驗證者多簽；2/3 驗證者勾結或被攻破時，橋上資金有風險 |
| 人工干預 | 2025 年 3 月 JELLY 事件：有人操縱小幣使 HLP 面臨巨額虧損，驗證者投票下架並以指定價格結算 |
| ADL | 2025 年 10 月大崩盤中，不少獲利部位被自動減倉 |
| 開源與存取 | 節點程式碼的開源程度有爭議；前端有地區封鎖 |

準確說法：**資產自我託管、交易紀錄公開可查，但治理與安全性高度依賴一小群驗證者。** 比 CEX 透明（不會發生 FTX 式的祕密挪用），但和以太坊的去中心化程度差距很大。

## 五、帳本膨脹問題

### 1. 先分清狀態與歷史

成長量約為「每秒交易數 × 每筆大小 × 時間」，對時間是線性。但 Hyperliquid 每秒可能有數萬到數十萬筆下單與撤單，斜率比以太坊大幾千倍。

| | 狀態（State） | 歷史（History） |
| --- | --- | --- |
| 內容 | 現在的餘額、持倉、掛單 | 過去每一筆下單、撤單、成交 |
| 驗證新區塊是否需要 | 需要，最好放在記憶體 | 不需要 |
| 是否持續成長 | 可設計成有上限 | 只增不減 |

策略：**狀態壓在有界範圍；歷史移出共識層。**

### 2. 控制狀態

訂單大多很短命，成交或撤單後就從狀態刪除，只留在歷史。另有硬性限制：

- 每個帳戶的掛單數量有上限（基本約一千張，成交量越大上限越高）。
- 最小下單金額約 10 美元，避免小單塞爆訂單簿。
- 請求額度與累積成交量成正比，取代 gas 的防垃圾機制。
- 新帳戶須先存入資金才能啟用。
- HyperEVM 的合約儲存仍以 gas 計價。

結果：狀態大小大致是「帳戶數 × 持倉數 + 目前掛單數」，隨用戶成長，不隨時間無限累積。

### 3. 處理歷史

- **快照同步**：節點定期把整個狀態寫成快照，新節點下載最近快照後跟上，不從創世區塊重播。
- **節點自行刪除**：官方節點文件提醒資料目錄成長很快，營運者須定期清理舊區塊和日誌；一般節點本來就不保存完整歷史。
- **外部存檔**：完整成交與訂單簿資料放在 AWS S3 公開存檔（requester-pays，下載者付流量費），另有區塊瀏覽器與資料商各自保存。

### 4. 代價

1. **硬體門檻高**：大記憶體、高速 SSD、好網路，驗證者自然少。
2. **歷史可得性要信任他人**：查舊交易實務上依賴 S3 存檔或索引商，放棄「任何人都能從頭獨立驗證」的理想。
3. **快照來源要信任**：比從頭重播弱，但在 BFT 鏈上是常見取捨。
4. **輕客戶端能力有限**：一般用戶難以不信任任何節點就驗證自己的帳戶狀態。

### 5. 與其他鏈比較

| | 狀態控制 | 歷史處理 |
| --- | --- | --- |
| 以太坊 | gas 計價儲存；研究中的 state expiry、Verkle 樹 | EIP-4444 歷史過期，交給 Portal Network 等 |
| Solana | 帳戶租金（rent）押金 | 驗證者只留近期帳本，完整歷史放 BigTable、Old Faithful 等存檔 |
| Hyperliquid | 訂單短命、掛單上限、速率限制 | 快照同步、節點自行刪除、S3 公開存檔 |
| ZK Rollup（如 Lighter） | 鏈下維護狀態 | 零知識證明保證正確，資料可用性交給以太坊 blob |

整個產業正在收斂到同一方向：**共識節點只保證狀態正確，歷史交給專門的存檔服務。**

## 六、其他主要玩家

- **dYdX v4**：Cosmos 應用鏈，驗證者在記憶體各自維護訂單簿，只把成交結果上鏈。
- **Lighter**：以太坊上的 ZK rollup，以零知識證明保證撮合正確，安全性依附以太坊。
- **GMX／Drift**：預言機定價加 LP 資金池，不需訂單簿深度，但 LP 是所有交易者的對手方。
- **Aster、edgeX** 等：類 Hyperliquid 或 L2 訂單簿的競爭者，主打手續費或空投激勵。
