# 字幕聲音與展場交付規格

[回主報告](../README.zh-TW.md)。以下為約 50 吋橫式螢幕的製作起點；實際螢幕、播放器及視距未確認前，不當成主辦單位規格。

## 畫面與觀看距離

16:9、50 吋的顯示面積約寬 111 公分、高 62 公分。以 1080p 畫布 44 px 字級計算，字框高度約 2.5 公分，實際字形依字型而變；3 公尺外是否能輕鬆閱讀必須現場試看。**同樣物理大小的字，4K 字級需約為 1080p 的兩倍；增加像素不會自動增加可讀性。**

| 元素 | 1080p 起點 | 4K 起點 | 使用方式 |
| --- | --- | --- | --- |
| 場景標題 | 64–84 px | 128–168 px | 每場一個重點，控制在短句 |
| 英文字幕 | 42–48 px | 84–96 px | 位於字幕區上行 |
| 繁體中文字幕 | 44–50 px | 88–100 px | 位於英文下行，避免過小 |
| 安全邊界 | 水平至少 96 px、垂直 54 px | 水平至少 192 px、垂直 108 px | 避免 overscan／展架遮擋 |
| 字幕保留區 | 底部約 20–25% 高度 | 相同比例 | 在構圖階段預留，必要時把 UI 上移 |

英中都用白字或近白字搭配穩定深色底。不要只靠細描邊壓在多變 UI 上；不用逐字跳動字幕。字型選具繁體字形且可嵌入／渲染的字型，先測「臺灣、介面、暫存器、設定、體驗」。平台能上傳字型不代表任何字型都可合法上傳。

雙語每個字幕單位原則上各一行；英文先抓 6–9 個詞、中文先抓 12–18 字，再依實際排版調整。較長句拆成連續字幕，不縮小到遠距離讀不清。一般停留約 3–5 秒；以最慢讀者實測調整，不靠固定字數規則硬切。

## 字幕製作流程

1. 定稿英文旁白及繁體語意稿，建立 EDT／HMI／LVGL／Tags 等詞彙表。
2. 生成最終旁白，再按實際音檔切句與對齊；不要直接沿用故事板估計時間。
3. 英文字幕對應實際說出的話，繁體字幕人工校對；UI 標籤保留當時的真實語言。
4. 匯出 `en.srt`、`zh-TW.srt`；確認 UTF-8、時間遞增、無負長度／無意重疊。
5. 現場主版本把雙語燒錄進影片，避免播放器忽略外掛字幕。保留無燒錄乾淨版供改語言。
6. 在 1080p 與 4K 各檢查一次；平台縮放可能改換行，不能只驗收其中一版。

靜音版保留能獨立說明操作的標題與雙語資訊。有聲版的旁白補充細節，不能承擔唯一的產品訊息。

## 聲音設計

英語旁白暫定清楚、中性、節奏穩定，避免廣告式誇張演出。中文配音若新增，獨立生成與重新對齊，不把英語時間碼硬套中文。旁白原檔優先保存 48 kHz WAV；供應商若只交其他取樣率／格式，保存原檔並另外轉換，不聲稱轉換增加原始音質。

音樂提案：無人聲、約 95–110 BPM、簡潔電子節奏、少量明亮音色，無強烈警報／低頻轟鳴。片尾收束或循環要在剪輯器處理，不假設模型說「loopable」就已無縫。

音效只在 3–5 個關鍵節點使用：標題進場、重點切換、完成提示。若實機沒有發聲，不把後製音效包裝成內建音效；錯誤通知場景盡量不用尖銳警報，以免影響攤位。

有聲 MP4 的試混目標可先設整體約 -16 LUFS integrated、true peak 不高於 -1 dBTP，旁白期間音樂比旁白低約 15–20 dB，再用聽感調整。這是本案工作值，非 Computex 廣播規定；檔案響度也不等於攤位聲壓，現場音量另依主辦規則與鄰攤環境調整。

若雲端工具缺少精確 ducking／響度測量，先輸出各音軌，用桌面工具完成混音再交 Claude 替換音訊。另出真正無音軌或全靜音版本，避免誤播。

## 輸出規格與檔案

| 項目 | 主要規格 | 備援 |
| --- | --- | --- |
| 畫布 | 3840×2160、16:9 | 1920×1080、16:9 |
| 幀率 | 預設固定 30 fps | 60 fps 僅在實機動態需要且播放器測試通過時 |
| 色彩 | SDR、Rec.709 | 不混入未正確轉換的 HDR 素材 |
| 容器／編碼 | MP4、H.264、常見 8-bit 4:2:0 | HEVC 僅作已測播放器的選配 |
| 參考碼率 | 4K 約 35–60 Mbps、1080p 約 12–20 Mbps | 平台限制時依 UI 細字與播放穩定調整 |
| 有聲音軌 | AAC、48 kHz、立體聲，能設定時約 256–320 kbps | 聲道／取樣率依實際播放器驗收 |
| 中間母檔 | 平台可提供時保存高品質中間格式 | 否則保存最高品質成片＋原始素材與模板 |

不能把 1080p 錄屏經 AI 放大、補造 UI 文字當成可靠 4K 細節。若原素材只有 1080p，以 1080p 乾淨呈現為優先；4K 可由高解析字卡與適當尺寸的實錄組合，清楚區分來源解析度。

最小交付組合共 8 個 MP4：90 秒主片與 30 秒版，各有 4K／1080p、雙語有聲／雙語靜音四種。另交兩語 SRT、無燒錄乾淨版（至少 1080p）、音訊分軌、模板／manifest、授權紀錄、播放說明。若縮減範圍，優先保留 1080p 靜音版與有聲版。

檔名例：`EHS_Computex_MAIN90_4K_EN-ZHTW_AUDIO_v01.mp4`；`EHS_Computex_LOOP30_FHD_EN-ZHTW_SILENT_v01.mp4`。檔名不用 final-final，發布版號另記於交付清單。

## 現場播放

製作在雲端，展場播放使用已下載本機影片。播放器一台主機、一個備援；兩份 USB／SSD，檔案 checksum 一致。若使用 FAT32，單檔大小受限制，實際格式必須以電視支援為準；不預設所有電視都支援 exFAT 或高碼率 4K。

在實際電視關閉 overscan、動態補幀或過強銳化等可能影響 UI 的設定並比較效果。測試 USB 或 HDMI 的實際播放路徑；關閉通知、螢幕保護、睡眠與自動更新干擾。斷網、重新開機、斷電復電後確認能恢復循環。

QR code 使用正式固定網址，先以至少三款手機在預期距離與展場亮度試掃；影片片尾之外再放固定實體 QR 看板，避免觀眾等下一輪。影片中保留可讀短網址。未確認公開網址之前不製作假 QR。
