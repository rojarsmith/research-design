# 01 C 語言是怎麼被創造出來的

研究日期：2026-10-19。本文整理 C 語言誕生的動機、技術譜系與標準化歷程，重點放在「為什麼它長成這樣」，因為這些設計決定直接影響後面兩個問題：編譯器怎麼做、處理器要具備什麼條件。年份與事件以 Dennis Ritchie 的〈The Development of the C Language〉與 WG14 官方頁面為主要依據，來源見 [05 來源](05-sources.zh-TW.md)。

## 一句話版本

C 不是從零設計出來的語言，而是 Bell Labs 的 Ken Thompson 與 Dennis Ritchie 為了「用高階語言寫作業系統、而且在很小的機器上跑得動」，把 BCPL 和 B 一路改造、再加上型別系統的結果。它的每一個特徵幾乎都對應到 1970 年代 PDP-11 的某個限制或能力。

## 技術譜系：CPL → BCPL → B → C

| 時間 | 語言 | 關鍵人物與機器 | 留給 C 的東西 | 被 C 改掉的東西 |
| --- | --- | --- | --- | --- |
| 1960 年代初 | CPL | 劍橋與倫敦大學 | 區塊結構、表達式語法的雛形 | 過於龐大，從未有完整實作 |
| 1967 | BCPL | Martin Richards（劍橋） | 「系統程式語言」的定位、大括號式的區塊、無型別的字（word）模型、以 `O-code` 中間碼達成可攜性 | 只有一種資料型別（機器字），沒有結構 |
| 1969 | B | Ken Thompson，PDP-7（Unix 初版機器） | 精簡後的 BCPL 語法、`++`/`--`、組合指定運算子、在很小的記憶體中可運作的編譯器 | 仍是無型別語言；「字」等於記憶體位址單位，在以位元組定址的機器上效能差 |
| 1971 至 1973 | New B → C | Dennis Ritchie，PDP-11 | 加入 `char`、`int`、指標型別、陣列與指標的對應關係、結構（`struct`）、前置處理器雛形 | 把「所有東西都是字」改成「有大小、有型別的物件存放在以位元組定址的記憶體中」 |

### 為什麼 B 不夠用

PDP-7 是字定址（word-addressed）機器，B 把整個世界看成一串字是合理的。1970 年換到 PDP-11 後出現三個問題：

1. PDP-11 以位元組定址，有 `char` 大小的資料與對應指令。B 的指標是字的索引，處理字元必須額外拆解，程式變慢也變醜。
2. PDP-11 將有浮點硬體，B 的單一型別無法表達不同大小的數值。
3. B 的實作採「threaded code」直譯，相對於組合語言太慢，寫不了核心。

Ritchie 的解法是給語言加上型別，讓編譯器知道每個物件的大小與擺放方式，因此可以直接產生機器指令。這一步奠定了 C 的本質：**C 是對一台「以位元組定址、有堆疊、能做整數運算與間接存取」的抽象機器的描述語言。** 後面評估處理器能否跑 C，就是在檢查處理器離這台抽象機器有多遠。

### 指標與陣列的關係從何而來

B 裡面宣告陣列會配置一個指標，再指向另一塊空間。Ritchie 在 C 裡改成「陣列名稱在表達式中轉換為指向第一個元素的指標」，這樣結構裡的陣列才不需要額外的指標欄位、初始化也不用特別處理。這就是今天 `a[i]` 等於 `*(a + i)` 的由來，也是 [實作練習](../labs/tinyc/README.md) 中 `tinyc` 直接用這個定義實作索引的原因。

## Unix 是 C 的第一個客戶，也是它存在的理由

- 1969 年的 Unix 以 PDP-7 組合語言寫成，1970 年移到 PDP-11 時又用組合語言重寫一次。每換一台機器就得重寫整個系統，這個痛點是 C 的直接動機。
- 1973 年，C 加入結構型別後，Unix 核心大部分以 C 重寫（Unix 第 4 版）。Ritchie 與 Thompson 在 1974 年的 CACM 論文〈The UNIX Time-Sharing System〉中正式對外描述這個系統。
- 1977 至 1979 年，Steve Johnson 的 Portable C Compiler（PCC）與 Unix 移植到 Interdata 8/32 的工作，證明「用 C 寫的系統可以靠重做編譯器後端就搬到另一種處理器」。這是「可攜性」第一次被實際驗證，也是 [02 編譯器](02-how-compilers-are-built.zh-TW.md) 討論前後端分離的歷史起點。

## 標準化：從 K&R 到 C23

| 版本 | 年份 | 代表性變化 | 對編譯器與處理器的意義 |
| --- | --- | --- | --- |
| K&R C | 1978 | Kernighan 與 Ritchie 的《The C Programming Language》成為事實標準 | 沒有函式原型，型別檢查鬆散；各家編譯器行為不一 |
| ANSI C（C89）／ISO C90 | 1989／1990 | 函式原型、`void`、`const`、標準函式庫、明確區分「未定義」「未指定」「實作定義」行為 | 第一次明文寫下抽象機器與實作可自由決定的範圍，例如 `CHAR_BIT` 至少 8、整數大小只規定下限 |
| C99 | 1999 | `//` 註解、`long long`、`inline`、變長陣列、`stdint.h`、指定初始化 | `stdint.h` 讓程式可以精確要求位元寬度，是嵌入式與跨架構程式的基礎 |
| C11 | 2011 | 執行緒與記憶體模型、原子操作、`_Alignas`、`_Generic`、匿名結構 | 多核心處理器的記憶體順序第一次進入語言層 |
| C17／C18 | 2018 | 勘誤為主，無新功能 | 多數工具鏈今日的預設或常用方言 |
| C23 | 2024 出版（ISO/IEC 9899:2024） | `nullptr`、`constexpr`、`typeof`、`#embed`、二補數成為唯一整數表示、移除 K&R 函式定義 | 「二補數唯一」代表標準終於放棄支援一補數與符號大小表示的處理器 |

標準委員會為 ISO/IEC JTC1/SC22/WG14。版本之間的差異可用 `__STDC_VERSION__` 查詢；[probe 實驗](../labs/probe/probe.c) 會印出這個值。

## C 的設計決定與硬體之間的對應

下表是理解整個主題的關鍵。左邊是語言特徵，右邊是處理器或 ABI 必須提供的東西：

| C 的特徵 | 背後的假設 | 處理器／工具鏈要提供的 |
| --- | --- | --- |
| `char` 是最小可定址單位，`sizeof(char) == 1` | 記憶體可以用位元組（或實作定義的最小單位）定址 | 位元組存取指令，或編譯器以遮罩模擬 |
| 指標可以指向任何物件並做算術 | 單一、線性的資料位址空間 | 暫存器間接定址、位址加法；哈佛架構需要額外處理 |
| 遞迴與區域變數 | 每次呼叫有獨立的框架 | 堆疊指標與相對定址，或軟體模擬的堆疊 |
| 函式指標、`switch` 跳躍表 | 可以跳到執行期才知道的位址 | 間接跳躍指令 |
| 有號整數、除法截斷朝零 | 二補數整數運算（C23 起為必要條件） | 加減乘除與比較指令；除法可由函式庫實作 |
| `volatile` | 記憶體對應 I/O 的存取不可省略 | 編譯器不得合併或刪除存取 |
| 未定義行為 | 允許編譯器不為錯誤程式付出成本 | 這是 C 能生成高效率程式的代價來源 |

這張表在 [03 處理器評估](03-processor-c-readiness.zh-TW.md) 會展開成可操作的檢查清單。

## 常見誤解

- **「C 是可攜組合語言」**：C 的運算定義在抽象機器上，編譯器可以重排、消去、改寫程式，只要可觀察行為不變。看 `-O2` 的輸出就能理解這一點，[實作練習](../labs/tinyc/README.md) 有 `-O0` 與 `-O2` 的對照。
- **「C 一開始就是標準化的語言」**：1978 到 1989 之間只有 K&R 這本書與 Unix 編譯器的實際行為；ANSI 標準化時花了大量篇幅處理既有程式碼的相容。
- **「C 的設計者預見了今天的用途」**：Ritchie 在回顧裡明說，C 的成功有很大一部分來自 Unix 的擴散與它「夠小、夠接近機器、又比組合語言好寫」，而不是周密的語言設計。
