# 03 如何評估一款處理器能否執行 C 編譯後的軟體

研究日期：2026-10-19。這個問題在實務上幾乎從不是「能不能」，而是「要付出多少代價、哪些 C 的能力會打折、工具鏈是否已經存在」。本文先列出 C 抽象機器對硬體的實際要求，再給出一套可以在一天內做完的評估流程，最後整理幾類已知困難的處理器。

## 先把問題拆成三層

| 層 | 問題 | 誰負責 | 若不滿足會怎樣 |
| --- | --- | --- | --- |
| 指令集層 | 硬體能否表達 C 抽象機器的基本操作 | 處理器設計者 | 編譯器要用多條指令或函式庫模擬，程式變大變慢；極端情況下某些 C 功能不可用 |
| 工具鏈層 | 是否有人為這個指令集寫了後端、ABI、啟動碼、函式庫 | 編譯器與 SDK 維護者 | 沒有後端就等於「不能跑 C」，不管硬體多強 |
| 執行環境層 | 程式需要的記憶體、I/O、作業系統服務是否存在 | 系統整合者 | hosted 程式（用 `printf`、檔案、`malloc`）跑不起來，freestanding 程式可以 |

「處理器能跑 C」在工程上的定義：**存在一條工具鏈，能把符合標準的 C 原始碼翻成這顆處理器的指令，並且產出的程式在合理的資源下通過一致性測試。** 所以評估的主要對象其實是工具鏈，硬體只決定代價。

## 指令集層：C 抽象機器的最低要求

以下每一項都對應 C 標準第 5 章與第 6 章的某個語意。打勾表示硬體直接支援，打叉不代表不能跑 C，而是編譯器要付出的代價。

### 必要條件（缺少就幾乎無法支援完整的 C）

1. **線性、可定址的資料記憶體**，而且 `char` 至少 8 位元（`CHAR_BIT >= 8`）。位元組定址最好；字定址機器（例如某些 DSP）會讓 `char` 變成 16 或 32 位元，這在標準內合法，但大量假設 8 位元位元組的程式碼會壞掉。
2. **整數加減、比較、位元運算**。乘除可由函式庫補（`libgcc`），但至少要有加法與移位。
3. **間接存取（透過暫存器中的位址讀寫記憶體）**。沒有這個就沒有指標，沒有指標就沒有 C。
4. **條件分支與間接跳躍**。`if`／迴圈需要前者，函式指標、`switch` 跳躍表、回傳需要後者。
5. **可重入的副程式呼叫機制**：堆疊，或至少能用軟體維護一個堆疊。遞迴與區域變數都靠它。8051 與早期 PIC 的硬體堆疊很小或不可定址，SDCC 與 XC8 因此預設把區域變數配置成靜態位置並做「重疊分析」，副作用是預設不支援遞迴。
6. **二補數整數**（C23 起為標準要求；C17 之前允許一補數與符號大小，但實務上幾乎無工具鏈支援）。

### 強烈影響效率的條件

| 硬體特徵 | 影響 | 缺乏時的典型對策 |
| --- | --- | --- |
| 足夠的通用暫存器（8 個以上） | 暫存器配置品質；區域變數是否需要一直進出記憶體 | 大量 spill；6502／8051 這類累加器機器效率低 |
| 暫存器加偏移量定址（`lw a0, -20(fp)`） | 存取區域變數、結構欄位的成本 | 先算位址再存取，每次多 1 至 2 條指令 |
| 乘法與除法指令 | 陣列索引、`%`、雜湊 | 呼叫 `__mulsi3`、`__divsi3`，慢 10 至 100 倍 |
| 大於 8 位元的 ALU 與位址 | `int` 至少 16 位元，指標寬度須能涵蓋全部記憶體 | 8 位元 MCU 上 `int` 是 16 位元、由兩條 8 位元運算組成 |
| 單一位址空間（von Neumann） | 指標能否同時指向 ROM 常數與 RAM 變數 | 哈佛架構（AVR、PIC、8051）需要「命名位址空間」或 `__flash`、`code` 修飾字，否則常數會被複製到 RAM |
| 非對齊存取或至少可預期的對齊規則 | 結構封裝、網路封包解析 | 編譯器插入對齊；錯誤的轉型造成 trap（SPARC、早期 ARM） |
| 硬體浮點 | `float`／`double` 效能 | 軟體浮點（`-mfloat-abi=soft`），慢 20 至 100 倍，仍是正確的 C |
| 原子操作與記憶體屏障 | C11 `<stdatomic.h>`、執行緒 | 單核心可用關中斷模擬；多核心沒有就無法正確實作 |

### 用 tinyc 的輸出對照

[tinyc](../labs/tinyc/README.md) 只用到 RV32I 的不到二十條指令加上 M 擴充的 `mul`、`div`、`rem`。把這個清單當成「最低可行指令集」來讀：

| C 結構 | tinyc 使用的指令 | 代表的硬體能力 |
| --- | --- | --- |
| 常數、變數讀寫 | `li`、`lw`、`sw`、`addi` | 立即數載入、暫存器加偏移存取 |
| 算術與比較 | `add`、`sub`、`mul`、`div`、`rem`、`slt`、`xori`、`seqz`、`snez`、`slli`、`srai` | ALU、比較結果可以變成 0／1 的值 |
| 控制流程 | `beqz`、`bnez`、`j` | 條件與無條件分支 |
| 函式 | `call`、`ret`、`sw ra`／`lw ra`、`sp` 的加減 | 回傳位址暫存器與可定址的堆疊 |
| 全域變數 | `la`、`.data`、`.zero` | 絕對定址，連結器可配置的資料區 |
| 與環境互動 | `ecall` | 系統呼叫或等價的陷阱機制 |

沒有乘法指令的 RV32I 核心仍然可以跑 tinyc 的範例，只要把 `mul`／`div`／`rem` 換成函式庫呼叫；這正是 `-march=rv32i` 與 `rv32im` 的差別。

## 工具鏈層：實際決定「能不能」的地方

評估一顆處理器時，依序確認：

1. **是否有 GCC 或 LLVM 後端、或成熟的第三方編譯器**（SDCC、IAR、Keil、廠商自製）。檢查方式：GCC 原始碼的 `gcc/config/` 目錄、`clang -print-targets`、SDCC 支援清單。後端是「upstream」還是只有廠商 fork 很重要，fork 常停在舊版本。
2. **ABI 文件是否公開**：參數傳遞、對齊、資料模型（ILP32／LP64 等）。RISC-V psABI、Arm AAPCS 是範例。沒有文件就無法混用不同編譯器的目的檔。
3. **執行期函式庫**：`libgcc`／`compiler-rt` 是否針對該架構實作（軟體除法、軟體浮點、64 位元運算）。
4. **C 函式庫與啟動碼**：newlib、picolibc、musl、廠商 SDK 的 `crt0` 與 linker script 範本。
5. **除錯與模擬**：GDB 後端、QEMU 或廠商模擬器、JTAG／SWD 探針支援。沒有模擬器會讓測試成本高很多。
6. **測試結果**：GCC testsuite（含 torture 測試）通過率、SuperTest 之類商用一致性測試、Csmith 隨機差分測試有無被使用。

## 一天內可完成的評估流程

目標：對一顆候選處理器產出「可以／可以但有代價／不可以」的結論與證據。[06 實測](06-target-comparison.zh-TW.md) 用 clang 內建的 19 個後端把第 2 至第 4 步跑過一遍，可作為對照樣本。

### 第 1 步：資料盤點（1 小時）

- 指令集手冊：資料寬度、暫存器數量、定址模式、是否有乘除、堆疊機制、位址空間是否統一。
- 工具鏈：版本、upstream 狀態、支援的 `-march`／`-mcpu` 選項、授權。
- 記憶體：Flash／RAM 大小，這決定 hosted 或 freestanding 以及能用哪個 libc。

### 第 2 步：編譯探針程式（1 小時）

用 [probe.c](../labs/probe/probe.c) 以交叉編譯器建置並執行（模擬器或開發板），記錄 `CHAR_BIT`、各型別大小、位元組序、`-1 >> 1`、`-7 / 2` 等實作定義行為。無法執行時至少用 `-S` 看組合語言，確認 `int` 的寬度與指標的處理方式。

### 第 3 步：代表性程式的程式碼大小與指令數（2 小時）

- 取 `tinyc/examples/` 的五個程式或自己的核心演算法，以 `-O0`、`-Os`、`-O2` 編譯，記錄 `.text` 大小（`size` 指令）與執行指令數（模擬器統計或週期計數器）。
- 同時在一個已知良好的參考架構（例如 RV32IM 或 Cortex-M4）上做相同測量，比值就是這顆處理器「跑 C 的代價」。沒有交叉工具鏈時，`labs/probe/compare_targets.py` 用 clang 就能取得大小、指令數與執行期函式呼叫清單。
- 特別觀察：區域變數是否在暫存器中、乘法是否變成呼叫、函式呼叫的序曲與尾聲有多長、常數陣列放在哪裡。

### 第 4 步：C 功能邊界測試（2 小時）

逐項確認並記錄：遞迴、函式指標、`switch` 大表、`long long`、浮點、`volatile` 存取是否被保留、`setjmp`／`longjmp`、可重入（中斷中呼叫 C 函式）、C11 原子。每一項寫一個 20 行以內的測試，在模擬器或板子上執行，不能執行的用 `-S` 檢視。

### 第 5 步：結論與證據（1 小時）

| 結論 | 判定條件 |
| --- | --- |
| 可以 | upstream 工具鏈、ABI 公開、探針與邊界測試全過、代價比值在 2 倍以內 |
| 可以但有代價 | 工具鏈存在但缺少某些功能（無遞迴、無浮點、`char` 非 8 位元）或代價比值大於 2 倍；需在編碼規範中限制 C 子集 |
| 不可以 | 沒有可用後端，或硬體缺少必要條件（無間接存取、無可用堆疊且無法模擬） |

## 已知困難或特殊的處理器類別

| 類別 | 代表 | 問題 | 工具鏈的處理 |
| --- | --- | --- | --- |
| 累加器式 8 位元 MCU | 8051、PIC16／18、6502 | 暫存器極少、硬體堆疊小且不可定址、哈佛架構 | SDCC／XC8 用靜態區域變數與重疊分析，預設禁止遞迴；需要 `__code`／`__data` 等記憶體修飾字 |
| 哈佛架構但暫存器充足 | AVR | 常數在 Flash，指標預設指 RAM | GCC 的 `__flash` 命名位址空間或 `pgm_read_*` 巨集；否則常數表被複製到寶貴的 RAM |
| 字定址 DSP | TI C2000、部分 SHARC | `CHAR_BIT` 為 16 或 32 | 合法的 C 實作，但 `uint8_t` 不存在、`sizeof(int) == 1`、處理位元組流需要手動封裝 |
| 堆疊機與特殊架構 | 早期 Java 處理器、某些可程式邏輯 | 沒有通用暫存器或沒有任意記憶體存取 | 通常只支援語言子集或透過自製編譯器 |
| GPU | NVIDIA、AMD | SIMT 執行模型、分離的記憶體空間、遞迴與函式指標受限 | CUDA C／OpenCL C 是 C 的方言與子集；可以跑 C 的大部分，但不是任意 C 程式 |
| 無乘除的極小核心 | RV32E、RV32I 無 M、Cortex-M0 的除法 | 乘除交給函式庫 | 正確但慢；對控制類程式通常可接受 |
| 多核心弱記憶體模型 | Arm、RISC-V、POWER | C11 原子與順序需要正確的屏障 | 後端必須正確對應 `memory_order`，否則資料競爭程式行為錯誤；單執行緒程式不受影響 |

## 常見的錯誤判斷

- **把「有 C 編譯器」等同於「能跑我的 C 程式」**：8051 上的 SDCC 是真正的 C 編譯器，但預設不允許遞迴，`int` 運算要四條指令。要用你的程式去測，不要只看規格表。
- **把「跑得慢」當成「不能跑」**：軟體浮點或軟體除法仍是正確的 C。要問的是能否滿足時間預算。
- **忽略 hosted 與 freestanding 的差別**：MCU 上沒有作業系統時，`printf` 要靠你提供 `_write`；這是環境層的問題，不是處理器不支援 C。
- **只看 `-O0`**：`-O0` 輸出反映編譯器最笨的策略，不反映處理器能力；比較時至少看 `-O2`。
- **忽略工具鏈的維護狀態**：停留在 GCC 4.x 的廠商 fork 代表沒有 C11 原子、較弱的診斷與安全性修補。
- **用架構家族名稱代替確切型號**：m68k 後端預設 68000 時乘除法全是函式呼叫，68020 則有指令；Cortex-M4 有沒有 F 決定 `float` 是硬體還是軟體。見 [06](06-target-comparison.zh-TW.md)。
