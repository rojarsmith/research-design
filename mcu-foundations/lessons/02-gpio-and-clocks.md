# 第三課 GPIO、接腳與時脈

這一課約 4 至 6 小時。目標是把「呼叫 `gpio_write()`，LED 就亮」拆成可以逐一驗證的因果鏈。讀完應該能解釋：為什麼程式寫對了暫存器，LED 仍然可能不亮；為什麼寫 0 反而讓 LED 亮。

## 一支接腳背後的四層設定

| 層 | 要回答的問題 | 常見的失敗 |
| --- | --- | --- |
| 時脈閘控 | 這個 GPIO 模組有沒有時脈 | 沒開時脈，寫入沒有效果或讀回 0 |
| 接腳複用 | 這支接腳交給 GPIO 還是 UART、timer 等周邊 | 接腳被其他功能佔用，寫輸出暫存器沒反應 |
| 方向與電氣 | 輸入或輸出、推挽或開汲極、上拉或下拉 | 輸入浮接時讀值亂跳；開汲極沒有上拉就拉不高 |
| 資料 | 輸出暫存器、輸入暫存器、原子的設定與清除 | 讀-改-寫被中斷打斷，另一支接腳的狀態被蓋掉 |

很多 MCU 在 reset 後關閉大部分周邊的時脈以省電，所以第一步通常是在時脈控制模組裡打開 GPIO 的時脈。這個模組的名稱、哪一個位元控制哪個 port、沒開時脈時存取會怎樣，各家都不同，要查 reference manual。接腳複用有時在 GPIO 模組裡，有時是獨立的 pin mux 模組。

## LED 為什麼可能低電位亮

看電路圖上 LED 的兩端接到哪裡。若 LED 的陽極經電阻接到 VDD，陰極接到 MCU 接腳，接腳輸出低電位時電流才會從 VDD 流進接腳，LED 才亮；這叫低電位有效。反過來接，就是高電位有效。

順便估電流：3.3 V 供電、LED 順向電壓約 2 V、電阻 1 kΩ，電流約 (3.3 − 2) ÷ 1000 ≈ 1.3 mA。接腳能吸入或輸出多少電流、整個 port 合計的上限，要查 datasheet 的電氣特性；LED 的順向電壓則依顏色與元件而定。

應用程式不應該知道 LED 是低電位有效。把它藏在板級的一層，例如 `board_led_set(true)`，換板子時只改這一層。

## 從 API 追到暫存器

一個 HAL 呼叫最後一定會變成對某個地址的讀寫。追法有三種，至少用其中兩種互相印證：

1. 讀 HAL 原始碼，追到最後的暫存器存取，記下暫存器名稱與位元。
2. 在 debugger 裡 step into 那個呼叫，觀察實際寫入的地址與值。
3. 打開 debugger 的周邊暫存器畫面，呼叫前後各看一次。

周邊暫存器畫面通常來自廠商提供的 SVD 檔，它用機器可讀的方式描述每個周邊的暫存器與位元欄位，CMSIS 的裝置標頭檔也從它產生。[CMSIS-SVD](https://open-cmsis-pack.github.io/svd-spec/main/index.html)

最直接的證明是：程式暫停時，用 debugger 直接改輸出暫存器的值，LED 跟著變。這一步跳過了所有軟體，證明你找到的暫存器真的控制那支接腳。

## 讀-改-寫與原子的設定、清除

`OUT |= (1u << 5)` 在 CPU 上是三步：讀出、修改、寫回。如果中斷在讀出之後、寫回之前發生，而 ISR 改了同一個暫存器的另一個位元，主程式寫回的舊值會把 ISR 的修改蓋掉。

常見的解法：

- 使用晶片提供的「只寫」設定、清除暫存器。一次寫入只影響寫 1 的位元，不需要先讀。
- 讀-改-寫期間短暫關中斷，並且接受這段時間就是其他中斷的額外延遲。
- Cortex-M4 可選配 bit-band 區域，提供對單一位元的原子操作；Cortex-M0+ 的使用手冊沒有這項功能。其他核心要查各自的 core manual。[Cortex-M4 Generic User Guide](https://support.arm.com/documentation/dui0553/latest/)

多位元的欄位，例如每支接腳 2 bits 的模式欄位，要先清掉整個欄位再寫新值。只用 OR 寫入，舊值和新值會混在一起。

## 為什麼不能靠 delay 猜頻率

空迴圈的執行時間取決於編譯選項、指令、Flash 等待週期、cache 與時脈。沒有可觀察效果的空迴圈，最佳化時甚至可以整個被刪掉。從「迴圈跑了多久」反推時脈，等於同時猜好幾個未知數。

可靠的方法是拿一個獨立的時間基準比對：

- 用邏輯分析儀或示波器量一支切換中的接腳。
- 讓 UART 用設定的 baud 送字元，電腦端能正確收到，代表時脈至少落在 UART 容許的誤差內；不能正確收到，先懷疑時脈設定。
- 用 timer 讓 LED 每秒切換一次，數 60 次並和手機碼錶比對。這只能抓出大錯，例如差了兩倍。
- 有些晶片能把內部時脈輸出到接腳；是否支援、輸出哪個時脈，要查 reference manual。

## 桌機實驗

[labs/02-gpio-registers/gpio_model.c](../labs/02-gpio-registers/gpio_model.c) 實作一個虛構的 GPIO 周邊：時脈閘控、模式欄位、上下拉、輸出與輸入暫存器、只寫的設定清除暫存器。板子接線也是虛構的：PA5 接低電位有效的 LED，PA13 接到 GND 的按鈕。暫存器配置不屬於任何廠商，但每個機制在真實晶片上都找得到對應。

```sh
cd labs/02-gpio-registers
gcc -std=c11 -Wall -Wextra -Werror -O2 -o gpio_model gpio_model.c
./gpio_model --trace
./gpio_model --test
```

`--trace` 印出每個 HAL 風格函式產生的暫存器讀寫，形式就像 debugger 的暫存器畫面。先預測 `board_led_set(1)` 會寫哪個暫存器、寫入什麼值，再看輸出。最後一段示範讀-改-寫被 ISR 打斷：PA6 被 ISR 寫成 1，又被主程式覆寫回 0。

`--test` 檢查七件事：沒開時脈時寫入無效、低電位有效的 LED、輸入模式下輸出值不會出現在接腳、模式欄位沒先清除的錯誤、替代功能接管接腳、浮接輸入讀值不可預期、讀-改-寫遺失更新。讀測試程式碼，把每一項對應到上面的四層設定。

[labs/02-gpio-registers/delay_demo.c](../labs/02-gpio-registers/delay_demo.c) 用兩種最佳化等級建置同一段延遲迴圈：

```sh
gcc -std=c11 -Wall -Wextra -Werror -O0 -o delay_O0 delay_demo.c
gcc -std=c11 -Wall -Wextra -Werror -O2 -o delay_O2 delay_demo.c
./delay_O0
./delay_O2
```

在一台 Windows 11 桌機上，沒有 volatile 的迴圈在 -O0 跑了約 83 ms，在 -O2 變成 0 ms；加了 volatile 的版本兩次都還在跑，卻「推算」出完全不同的頻率。你的數字會不同，重點是同一段原始碼可以對應到差異極大的時間。

## 上板實作

1. 從電路圖找出 LED 與按鈕接到哪支接腳、LED 是高或低電位有效、按鈕有沒有外部上拉。
2. 從 reference manual 找出：該 GPIO port 的時脈開關位元、這支接腳的模式欄位、輸出暫存器、設定清除暫存器（若有）、接腳複用的設定位置。
3. 執行官方 blink。暫停後打開周邊暫存器畫面，記下這些暫存器的值。
4. 程式暫停時，用 debugger 直接改輸出暫存器，確認 LED 跟著變。
5. step into HAL 的寫入函式，記下實際寫入的地址與值，和第 2 步查到的位元對照。
6. 自己寫一版不經 HAL 的初始化：開時脈、設模式、用設定清除暫存器控制 LED。
7. 量測：用邏輯分析儀量 LED 接腳的切換週期；沒有儀器時用 60 秒碼錶法。各用 -O0 與 -O2 建置一次延遲迴圈版本，比較結果。

故障注入，每項都要能恢復：

- 用 debugger 清掉 GPIO 的時脈開關位元，再寫輸出暫存器，記錄讀回的值與 LED 狀態，然後恢復。
- 把 LED 接腳設成輸入模式，觀察 LED。
- 若按鈕沒有外部上拉，關掉內部上拉，連續讀輸入暫存器並記錄讀值。

除錯介面的接腳在很多晶片上也能當 GPIO 用。誤把它們設成 GPIO 後，debugger 可能再也連不上；這時要用 reset 狀態下連線或晶片的特殊開機模式恢復。動接腳設定之前，先在電路圖和 reference manual 確認哪些接腳是除錯介面。

| 驗收條件 | 要留下的證據 |
| --- | --- |
| 解釋 LED 為何可能低電位亮 | 電路圖截圖或描述、計算的電流、寫入值與 LED 狀態的對照 |
| 從 API 追到硬體設定 | HAL 呼叫、暫存器地址與值、reference manual 章節，三者互相對得上 |
| 不能只靠 delay 猜頻率 | 用獨立時間基準量到的結果，以及 -O0 與 -O2 的差異 |

## 先自行回答

1. LED 陽極經 1 kΩ 接 3.3 V，陰極接 PA5。PA5 輸出 1 時 LED 亮還是滅？
2. 寫入 GPIO 模式暫存器後讀回 0，列出兩個可能原因。
3. 主程式執行 `OUT |= LED1`，ISR 執行 `OUT ^= LED2`。哪一邊的修改可能遺失？怎麼修？
4. 某延遲迴圈在 -O0 執行 1,000,000 次花了 62 ms。能不能推出 CPU 頻率？
5. 按鈕接到 GND，沒有任何上拉。放開時讀到什麼？

### 解析

1. 滅。兩端都接近 3.3 V，沒有電流流過 LED。
2. 例如時脈沒開、寫錯 port 或地址、該暫存器被鎖定保護、該接腳被保留給其他功能。逐一用 debugger 和手冊排除，不要一次改好幾個地方。
3. ISR 對 LED2 的修改可能遺失，因為主程式寫回的是被打斷前讀到的舊值。改用只寫的設定清除暫存器，或在讀-改-寫期間短暫關中斷。
4. 不能。迴圈每次要幾個週期取決於編譯結果、等待週期和 cache；這個數字也可能在換最佳化等級後完全改變。
5. 接腳浮接，讀值不可預期，可能隨手靠近或雜訊改變。要開內部上拉，或在電路上加上拉電阻。
