## 1 範圍與用語

### 1.1 範圍

minilang 是一門小型動態型別語言，有數值、字串、布林、`nil`、列表、一級函式與閉包、詞法區塊、`while` 迴圈與例外。程式是一個原始碼檔，從上往下執行，唯一的輸出是 `print` 寫出的文字。沒有模組、沒有輸入，也沒有其他 I/O。

參考引擎是儲存庫提交 `518b23b` 的樹走訪直譯器 `examples/minilang/minilang.py`（**tree**）、Python 位元組碼 VM `examples/minilang-vm/minilang_vm.py`（**vm**），以及由 `minilang_c.py` 驅動的 C VM `examples/minilang-c/mlvm.c`（**c**）。

### 1.2 規則的分類

| 用語 | 意義 |
| --- | --- |
| **明定（specified）** | 規範性。符合規格的實作必須完全照做；三個參考引擎都是如此 |
| **實作定義（implementation-defined）** | 由各實作在本文給的範圍內自行選擇並寫成文件；附錄 B 記錄參考引擎的選擇 |
| **舊有行為（legacy）** | 參考引擎現在的行為，1.0 保留，但標為**變更提案**（附錄 C）。Full 一致性層級必須照做，Core 層級不規定，所以 Core 實作可以直接採用提案。仿 ECMAScript 的 Annex B |

「必須」是對實作的要求；「是錯誤」表示該情況會引發所指名的錯誤，絕不是未定義行為。

### 1.3 執行結束的方式

一次執行只會以下列四種方式之一結束（10.1 節）：**正常完成**；在任何陳述執行前因**語法錯誤**停止；因**未捕捉的執行期錯誤**（沒有被任何 `try` 接住的執行期錯誤或被拋出的值）停止；或因**致命錯誤**停止，也就是會結束程式且 `try` 接不到的情況。1.0 的致命錯誤只出現在參考引擎讓宿主例外逸出的地方；10.7 節逐一列出，提案 P5 會移除其中大部分。

### 1.4 記號

文法規則用 EBNF：`|` 為選擇、`( )` 為分組、`?` 為可省略、`*` 為零或多次、`"x"` 為字面 token。訊息中的 `T` 代表某個值的 `type()` 名稱（4.1 節）。測試以 `spec: 7.4` 的形式引用節號。

## 2 詞法結構

### 2.1 原始碼文字

程式是從 UTF-8 檔案讀出的 Unicode 碼位序列。行以 LF 結束；CR 是空白。行號從 1 起算，每一行都算，包括註解行、空行與字串字面值內的行。位元組順序標記（BOM）不是空白：以 BOM 開頭的檔案是語法錯誤 `unexpected character '﻿'`。

### 2.2 空白與註解

空格、Tab、CR、換頁與垂直 Tab 用來分隔 token，此外沒有作用。字串外的 `#` 開始一個到行尾為止的註解。其他 Unicode 空白（U+00A0、U+3000）是否算空白由實作定義。

### 2.3 識別字與關鍵字

```text
IDENT    := ( letter | "_" ) ( letter | digit | "_" )*      -- 不能是關鍵字
keywords := let fn if else while return break true false nil and or not throw try catch
```

`letter` 是 `A`-`Z` 與 `a`-`z`，`digit` 是 `0`-`9`。識別字區分大小寫。識別字能否含非 ASCII 的字母與數字由實作定義。

### 2.4 數字字面值

```text
NUMBER := digit+ ( "." digit+ )?
```

沒有小數部分的字面值是整數（允許前導零：`007` 是 7）；有小數部分的是浮點數，取最接近該十進位數的 binary64 值。字面值沒有正負號（`-1` 是對 `1` 套用一元負號）、沒有指數（`1e5` 是數字 `1` 後面接名稱 `e5`）、沒有十六進位，小數點兩側都要有數字（`1.` 與 `.5` 都是語法錯誤 `unexpected character '.'`）。整數字面值本身沒有長度上限。1.0 中由實作定義、並有提案 P7 的是：字面值中的非 ASCII 數字字元，以及超過 4,300 位數的整數字面值。

### 2.5 字串字面值

```text
STRING := '"' ( char | escape )* '"'
escape := "\n" | "\t" | "\"" | "\\"
```

反斜線後接其他字元是語法錯誤 `bad escape sequence`，回報在反斜線所在行；沒有 `\u`、`\r` 或 `\0`。字串可以直接含換行與 Tab，內容照原樣保留。到檔尾仍未結束的字串是語法錯誤 `unterminated string`，回報在字串開始的行。

### 2.6 運算子與標點

```text
==  !=  <=  >=  +  -  *  /  %  (  )  {  }  [  ]  ,  ;  =  <  >
```

先比對兩字元運算子。任何不能開始 token 的字元是語法錯誤 `unexpected character C`，C 是該字元經 Python `repr()` 寫出的形式（`'@'`、`'!'`）。邏輯運算子是關鍵字 `and`、`or`、`not`。

## 3 語法

### 3.1 文法

```text
program    := statement* EOF
statement  := "let" IDENT "=" expression ";"
            | "fn" IDENT "(" params? ")" block
            | "if" "(" expression ")" block ( "else" ( "if" ifrest | block ) )?
            | "while" "(" expression ")" block
            | "return" expression? ";"
            | "break" ";"
            | "throw" expression ";"
            | "try" block "catch" "(" IDENT ")" block
            | block
            | expression ";"
ifrest     := "(" expression ")" block ( "else" ( "if" ifrest | block ) )?
block      := "{" statement* "}"
params     := IDENT ( "," IDENT )*
expression := assignment
assignment := logicOr ( "=" assignment )?          -- 目標規則見 3.4
logicOr    := logicAnd ( "or" logicAnd )*
logicAnd   := equality ( "and" equality )*
equality   := comparison ( ( "==" | "!=" ) comparison )*
comparison := term ( ( "<" | "<=" | ">" | ">=" ) term )*
term       := factor ( ( "+" | "-" ) factor )*
factor     := unary ( ( "*" | "/" | "%" ) unary )*
unary      := ( "-" | "not" ) unary | postfix
postfix    := primary ( "(" args? ")" | "[" expression "]" )*
args       := expression ( "," expression )*
primary    := NUMBER | STRING | "true" | "false" | "nil" | IDENT
            | "(" expression ")" | "[" args? "]" | "fn" "(" params? ")" block
```

以 `fn` 開頭且後面接識別字的陳述是函式宣告；`fn` 後面接 `(` 則開始一個運算式陳述。

### 3.2 陳述

沒有空陳述（單獨的 `;` 是 `unexpected token ';'`），`let` 一定要有初始值，`if` 與 `while` 的本體一定是區塊，`catch` 恰好命名一個變數，列表、引數與參數都不允許結尾逗號。

### 3.3 優先順序

由低到高：指派（右結合）；`or`；`and`；`==` `!=`；`<` `<=` `>` `>=`；`+` `-`；`*` `/` `%`；一元 `-` 與 `not`；呼叫與索引。所有二元運算子都是左結合，所以比較不會串接：`1 < 2 < 3` 是拿布林 `true` 和 `3` 比較，屬執行期錯誤（5.3 節）。`not 1 == 2` 是 `(not 1) == 2`。

### 3.4 指派目標

`=` 的左邊去掉括號後必須是名稱或索引運算式：`(a) = 1` 會指派 `a`，`f()[0] = 1` 會指派進 `f()` 回傳的列表。其他情況是語法錯誤 `invalid assignment target`，回報在 `=` 所在行。

### 3.5 語法錯誤

整個檔案在任何陳述執行前就完成詞法與語法分析，所以只要有語法錯誤，即使位於永遠不會執行的程式碼，程式也什麼都不印。語法錯誤附行號與下列訊息之一：

| 訊息 | 行號 |
| --- | --- |
| `unexpected character C`（C 為 Python `repr()` 形式） | 該字元 |
| `unterminated string` | 開頭引號 |
| `bad escape sequence` | 反斜線 |
| `expected X but found K` | 實際遇到的 token |
| `unexpected token V` | 實際遇到的 token |
| `unexpected end of input, missing '}'` | 未關閉的 `{` |
| `invalid assignment target` | `=` |

X 是 `a variable name`、`a parameter name`、`'{'`，或加上引號的預期 token（`';'`、`')'`、`'='`）；K 是遇到的 token 種類：運算子或關鍵字本身，或 `IDENT`、`NUMBER`、`STRING`、`EOF`。V 是 token 的值經 Python `repr()` 寫出的形式（`';'`、`'else'`、`5`、`'abc'`），或 `EOF`。訊息文字只在 Full 層級要求（15.1 節）。

## 4 值與型別

### 4.1 型別

| `type()` | 值 | 說明 |
| --- | --- | --- |
| `nil` | `nil` | |
| `bool` | `true`、`false` | 不是數值：`true + 1` 是錯誤，`true == 1` 為假 |
| `number` | 整數與浮點數 | 兩種表示、一個型別名稱；見第 12 節 |
| `string` | 不可變的 Unicode 碼位序列 | 第 13 節 |
| `list` | 可變的值序列 | 參考語意 |
| `function` | 使用者函式與標準函式 | 第 9 節 |

### 4.2 列表

列表值是參考：指派、傳參數與 `push` 都共用同一個列表，索引指派與 `push`、`pop` 的修改對所有持有者可見。兩個列表的 `a + b` 會產生新列表。列表可以包含自己。

### 4.3 函式

函式是值：可以儲存、傳遞、回傳與比較（比身分）。每次求值 `fn` 運算式或宣告都會產生新的函式。

## 5 真假值、相等與順序

### 5.1 真假值

`nil` 與 `false` 為假；其他值都為真，包括 `0`、`0.0`、`""` 與 `[]`。v 為假時 `not v` 是 `true`，否則是 `false`。

### 5.2 相等

`==` 與 `!=` 永遠不會失敗。兩個值相等的條件是：

- 都是布林且值相同（布林永遠不等於數值）；
- 都是數值且數學值相同；整數與浮點數精確比較，所以 `1 == 1.0`，但 `9007199254740993 != 9007199254740992.0`；NaN 不等於任何值，包括自己；
- 都是字串且碼位相同；
- 都是 `nil`；
- 是同一個列表或同一個函式（比身分，不比內容）。

不同型別的值永遠不相等。

### 5.3 順序

`<`、`<=`、`>`、`>=` 接受兩個數值（如 5.2 節精確比較；任何與 NaN 的比較都為假）或兩個字串（逐碼位比較，前綴排在較長字串之前）。其他組合是執行期錯誤 `'OP' expects two numbers or two strings, got T1 and T2`。

## 6 運算式

### 6.1 求值順序

運算元由左到右求值，而且在運算子檢查型別之前全部求完：二元運算子先求兩側，呼叫先求被呼叫者再依序求每個引數，索引讀取先求物件再求索引，索引指派依序求物件、索引與值。之後才做該運算的檢查，所以 `5(print("a"))` 會先印出 `a` 再失敗，`y = print("side")` 也會先印出再因 `y` 未宣告而失敗。

### 6.2 邏輯運算子

`a and b`：`a` 為假時是 `a`，否則是 `b`；`a or b`：`a` 為真時是 `a`，否則是 `b`。兩者回傳運算元本身而不是布林，而且只在需要時才求 `b`。

### 6.3 算術

| 運算子 | 運算元 | 結果 | 運算元不符 |
| --- | --- | --- | --- |
| `+` | 兩個數值；兩個字串；兩個列表 | 和；串接；新列表 | `'+' expects two numbers, two strings or two lists, got T1 and T2` |
| `-` `*` | 兩個數值 | 差、積 | `'OP' expects two numbers, got T1 and T2` |
| `/` `%` | 兩個數值 | 見 12.3、12.4 節 | 同上；除數為零是 `division by zero` |
| 一元 `-` | 一個數值 | 取負 | `unary '-' expects a number, got T` |

沒有字串重複、沒有隱含轉換，也沒有次方運算子。

### 6.4 索引

`x[i]` 讀取列表的第 `i` 個元素，或字串的第 `i` 個碼位（得到一個碼位長的字串）。`i` 必須是值為整數的數值；像 `1.0` 這樣值為整數的浮點數也接受。負索引從尾端算起（`-1` 是最後一個）。錯誤有：`index must be an integer, got T`（非數值或非整數值）、`index I out of range for length N`（I 是索引的整數值，大小不限）、`cannot index a T`。索引指派 `x[i] = v` 需要列表（`can only assign into a list, got T`），以同樣方式檢查索引，存入 `v`，整個運算式的值是 `v`。舊有行為（P5）：以無限大或 NaN 浮點數作索引是致命錯誤。

### 6.5 指派

`name = v` 存入 `name` 最近的既有繫結（7.3 節），運算式的值是 `v`。指派永遠不會宣告變數，見 7.6 節。

## 7 作用域與閉包

### 7.1 宣告

`let name = e;` 先求 `e`，再於目前作用域繫結 `name`。在同一作用域宣告已存在的名稱會取代它的值，不是錯誤。`fn name(...) {...}` 在陳述執行時於目前作用域繫結 `name`；宣告不會提升，所以在宣告執行前呼叫函式會得到 `undefined variable`。函式的參數與本體最外層共用一個作用域，所以本體裡的 `let a = ...` 會取代參數 `a`。

### 7.2 作用域

程式最外層是全域作用域。每個區塊（`{ }`，包括 `if`、`while`、`try`、`catch` 與函式的本體）都在一個新作用域中執行，該作用域巢狀於區塊出現的作用域；迴圈本體每次迭代都得到新的作用域。`catch` 變數繫結在處理區塊的作用域。作用域結束後，其中的繫結除了透過閉包之外都看不到。

### 7.3 名稱解析

名稱在每次使用時才解析：先找使用處所在的作用域，再依序往外找，直到全域作用域。函式本體的外層作用域是函式被建立之處的作用域。因為解析發生在使用時，函式可以引用在它之後才宣告的全域變數或區域函式，只要宣告在呼叫前已經執行；互相遞迴的區域函式，以及 `let f = fn() { ... f() ... }`，都能運作。

### 7.4 閉包建立後才出現的繫結（舊有行為，P2）

7.3 節的搜尋看的是**使用當下**已存在的繫結。如果外層作用域的某個 `let` 在閉包建立之後才執行，閉包之後對該名稱的使用會找到新的繫結，即使先前的使用找到的是更外層的繫結：

```text
let x = "outer";
fn test() {
  fn show() { return x; }
  let a = show();          # "outer"：test 的作用域此時還沒有 x
  let x = "inner";
  print(a, show());        # outer inner
}
```

指派也照同一規則。三個引擎都是這樣，Full 層級必須照做；提案 P2 會改成靜態繫結。

### 7.5 閉包

函式會保留其建立處的作用域，並引用其中的變數而不是值的複本：共用同一變數的閉包看得到彼此的指派，工廠函式呼叫兩次則建立兩組獨立的變數。

### 7.6 未定義的名稱

讀取沒有繫結的名稱是執行期錯誤 `undefined variable 'NAME'`。指派給這種名稱是 `assignment to undefined variable 'NAME'`；沒有隱含的全域變數。

## 8 控制流程

### 8.1 if

條件只求一次；為真（5.1 節）時執行第一個區塊，否則執行 `else` 部分（若有）。`else if` 串接是巢狀的 `if` 陳述。

### 8.2 while

每次迭代前求條件，條件為真就執行本體。

### 8.3 break

`break` 結束目前正在執行的最內層迴圈。舊有行為（P3）：該迴圈不必在同一個函式裡。在本身沒有迴圈的函式中執行 `break`，會結束呼叫端最內層的迴圈，可跨越任意層呼叫，包括條件式呼叫了該函式的迴圈，而且 `try` 擋不住。整個呼叫鏈上都沒有正在執行的迴圈時，`break` 是致命錯誤。

### 8.4 return

`return e;` 以值 `e` 結束目前的函式呼叫；`return;` 回傳 `nil`。它會離開函式內的迴圈與 `try` 區塊。舊有行為（P4）：在任何函式之外的最外層使用 `return` 是致命錯誤，`try` 接不到。

## 9 函式與呼叫

### 9.1 函式值

`fn name(p1, ..., pn) { body }` 與 `fn(p1, ..., pn) { body }` 建立恰有 n 個參數的函式。函式的文字（13.3 節）是 `<fn name>`；由 `fn` 運算式建立的函式即使存進變數，文字仍是 `<fn <anonymous>>`。標準函式的文字是 `<builtin name>`。

### 9.2 呼叫

`f(a1, ..., am)` 先求 `f` 與各引數（6.1 節），然後：若 `f` 不是函式，是執行期錯誤 `cannot call a T`；若 m 不等於 n，使用者函式是 `<fn name> expects N argument(s), got M`，標準函式是 `name() expects N argument(s), got M`（`print` 接受任意個數）。否則在新作用域中執行本體，參數繫結到引數。每次呼叫使用者函式會增加一個框架；14.1 節限制框架數。

### 9.3 回傳值

呼叫的值是結束它的 `return` 的值；本體執行完而沒有 `return` 時是 `nil`。

## 10 錯誤與例外

### 10.1 錯誤種類

| 種類 | 發生時機 | `try` 能否接住 | 回報內容 |
| --- | --- | --- | --- |
| 語法錯誤 | 任何陳述執行前（3.5 節） | 不能 | 行號與訊息 |
| 執行期錯誤 | 運算失敗（第 6、7、9、11、14 節） | 能，接到的是訊息字串 | 行號與訊息 |
| 被拋出的值 | `throw e;` | 能，接到的是該值 | 行號與該值的文字 |
| 致命錯誤 | 10.7 節 | 不能 | 由實作定義 |

從未執行的程式碼中的執行期錯誤永遠不會發生。

### 10.2 throw 與 try/catch

`throw e;` 求 `e` 並將其拋出。`try { A } catch (name) { B }` 執行 `A`；若 `A` 中（包括它呼叫的函式中，這些呼叫會被展開）發生執行期錯誤或拋出值，就執行 `B`，並把 `name` 繫結到接到的值。處理區塊可以巢狀：錯誤發生處外層最近的 `try` 接住它。`B` 裡發生的錯誤交給再外一層的 `try`。沒有 `finally`。展開會恢復呼叫深度，所以接住堆疊溢位之後，程式可以再次遞迴到完整深度。

### 10.3 執行期錯誤作為值

接到的執行期錯誤是不含行號的訊息字串。訊息如下：

| 情況 | 訊息 |
| --- | --- |
| 未定義的名稱 | `undefined variable 'NAME'` |
| 指派給未定義的名稱 | `assignment to undefined variable 'NAME'` |
| `+` 的運算元不符 | `'+' expects two numbers, two strings or two lists, got T1 and T2` |
| `-` `*` `/` `%` 用在非數值 | `'OP' expects two numbers, got T1 and T2` |
| 順序比較的運算元不符 | `'OP' expects two numbers or two strings, got T1 and T2` |
| 一元負號 | `unary '-' expects a number, got T` |
| 除數為零 | `division by zero` |
| 索引不是整數值 | `index must be an integer, got T` |
| 索引超出範圍 | `index I out of range for length N` |
| 索引非列表、非字串 | `cannot index a T` |
| 索引指派到非列表 | `can only assign into a list, got T` |
| 呼叫非函式 | `cannot call a T` |
| 引數個數不符 | `<fn NAME> expects N argument(s), got M`；`NAME() expects N argument(s), got M` |
| 超過呼叫深度 | `stack overflow (max call depth 400)` |
| 標準函式 | 第 11 節 |

精確的訊息文字在 Full 層級要求。Core 層級只要求接到的執行期錯誤是字串，文字由實作定義。

### 10.4 錯誤行號

| 錯誤 | 回報的行 |
| --- | --- |
| 二元或一元運算子 | 運算子 token |
| 呼叫（非函式、引數個數、堆疊溢位、標準函式引發的任何錯誤） | 呼叫的 `(` |
| 索引讀取 | `[` |
| 索引指派、指派給未定義名稱 | `=` |
| 未定義的名稱 | 該名稱 |
| `throw` | `throw` 關鍵字 |

函式內的錯誤回報在發生處，不是在呼叫處。

### 10.5 未捕捉的錯誤

未捕捉的執行期錯誤以其行號與訊息結束執行。未捕捉的拋出值以 `throw` 的行號結束執行，訊息是該值的文字（13.3 節）：`throw [1, "a", nil];` 回報 `[1, a, nil]`。文字在拋出時就計算，所以拋出沒有文字的值（包含自己的列表）會在 `throw` 處成為致命錯誤，即使在 `try` 內也一樣（舊有行為，P5）。

### 10.6 throw nil（舊有行為，P1）

`throw nil;` 被接成字串 `"nil"` 而不是 `nil`，未捕捉時回報訊息 `nil`。Full 層級必須照做；提案 P1 會改成繫結 `nil`。

### 10.7 致命錯誤

下列情況會立刻結束程式；`try` 接不到，之前的陳述已經執行並輸出，回報方式由實作定義。每一項都是舊有行為，也都有對應的提案。

| 情況 | 節 | 提案 |
| --- | --- | --- |
| 最外層的 `return` | 8.4 | P4 |
| 沒有正在執行的迴圈時的 `break` | 8.3 | P3 |
| 把大到無法轉成浮點數的整數轉成浮點數：與浮點數運算元做算術（`+ - * / %`），或傳給 `num()`（比較永遠不會轉換） | 12.3 | P5 |
| 大到無法轉成浮點數的整數商 | 12.3 | P5 |
| 把超過 4,300 位數的整數轉成文字（`print`、`str`、被拋出的值、索引錯誤訊息） | 14.2 | P5 |
| 以無限大或 NaN 浮點數作索引 | 6.4 | P5 |
| 拋出無法產生文字的值 | 10.5 | P5 |
| 在任何函式之外把包含自己的列表、或巢狀深於實作上限的列表轉成文字（在函式內：見附錄 B） | 14.3 | P5 |

實作註記：在參考引擎中，這些是逸出直譯器的 Python 例外（`ReturnSignal`、`BreakSignal`、`OverflowError`、`ValueError`、`RecursionError`）；C VM 在回報中重現同樣的型別名稱。

## 11 標準函式

標準函式是 `print`、`len`、`push`、`pop`、`str`、`num`、`type` 與 `clock`。它們引發的錯誤是執行期錯誤，行號為呼叫的 `(` 所在行。

### 11.1 print(v1, ..., vn)

寫出各引數的文字（13.3 節），以一個空格分隔，最後換行；沒有引數時寫出空行。回傳 `nil`。

### 11.2 len(v)

字串的碼位數或列表的元素數；其他情況是 `len() expects a string or list, got T`。

### 11.3 push(list, v)

把 `v` 加到尾端並回傳同一個列表；第一個引數不是列表時是 `push() expects a list`。

### 11.4 pop(list)

移除並回傳最後一個元素；空列表或非列表是 `pop() expects a non-empty list`。

### 11.5 str(v)

`v` 的文字（13.3 節）；字串的 `str(s)` 就是該字串。

### 11.6 num(v)

- 字串：依 12.6 節的文法轉換。
- 數值：同值的浮點數（`num(3)` 是 `3.0`，印出為 `3`）。舊有行為（P5）：大到無法轉成浮點數的整數是致命錯誤。
- 舊有行為（P6）：`true` 得 `1.0`，`false` 得 `0.0`。
- 其他值，或文法不接受的字串，是執行期錯誤 `num() cannot convert R`。舊有行為（P6）：R 是該值經 Python `repr()` 寫出的形式：`None`、`True`、`'abc'`、`"it's"`、`[None, 1, 'a']`、`<fn f>`。

### 11.7 type(v)

4.1 節的型別名稱。

### 11.8 clock()

一個以秒為單位的浮點數，用來量測經過時間。起點、解析度，以及時鐘能否被調回，都由實作定義（所有參考引擎都讀牆上時鐘，單位為自 Unix 紀元起的秒數，同 Python 的 `time.time()`）；測試只檢查它是正數，以及第二次呼叫的值不比第一次小。

### 11.9 標準函式是全域變數

標準函式和其他繫結一樣位於全域作用域：可以被重新指派（`print = fn(x) {...};`）或被遮蔽（在區塊中 `let len = 5;`），之後所有解析到該繫結的使用都受影響。

## 12 數值

### 12.1 整數

整數沒有大小上限；整數運算是精確的（`9223372036854775807 + 1` 是 `9223372036854775808`）。唯一的限制在與文字之間的轉換（14.2 節）。

### 12.2 浮點數

浮點數是 IEEE 754 binary64，採就近偶數捨入。溢位得到無限大，無效運算得到 NaN，都不是錯誤：把 `1.0` 乘 10 四百次會到 `inf`，`inf - inf` 是 `nan`。浮點數來自有小數部分的字面值、`num()`、`/`，以及任何有浮點數運算元的運算。

### 12.3 混合運算與除法

- 兩個整數的 `+ - *` 得整數；有浮點數運算元時，整數先轉成最接近的浮點數，結果是浮點數。
- `a / b` 中 `b` 為零（整數 `0`、`0.0` 或 `-0.0`）是 `division by zero`，浮點數也一樣。
- 兩個整數的 `a / b`：把精確的商捨入成最接近的浮點數；若該浮點數是整數值，結果是與它等值的整數，否則就是該浮點數。所以 `6 / 3` 是整數 `2`，`7 / 2` 是 `3.5`。舊有行為（P9）：因為先捨入，超過 2^53 的整除商並不精確：`9007199254740993 / 1` 是 `9007199254740992`。大到無法轉成浮點數的商是致命錯誤（舊有行為，P5）。
- 整數與浮點數之間的比較（`== != < <= > >=`）是精確的，永遠不會溢位。
- 舊有行為（P5）：其他必須把過大整數轉成浮點數的運算都是致命錯誤。

### 12.4 餘數

`a % b` 的正負號與 `b` 相同（向下取整除法）：`-5 % 3` 是 `1`，`5 % -3` 是 `-1`，`-5.5 % 2` 是 `0.5`。兩個整數得整數，否則得浮點數。`b` 為零是 `division by zero`。

### 12.5 數值的文字

數值的文字，用於 `print`、`str` 與錯誤訊息：

- 整數：十進位數字，負數加 `-`。
- 值為整數的浮點數，包括 `-0.0`：與它相等的精確整數，以十進位寫出（`2.0` 是 `2`，`-0.0` 是 `0`，`1e22` 是 `10000000000000000000000`，以 `1e22 * 10` 算出的 `1e23` 是 `99999999999999991611392`）。
- 無限大與 NaN：`inf`、`-inf`、`nan`。
- 其他浮點數：能讀回同一浮點數的最短十進位數字串，寫法同 Python 的 `repr()`：0.0001 <= |x| 時用一般寫法（`0.1`、`0.30000000000000004`、`0.0001`），更小時用指數寫法（`1e-05`、`1.5e-07`、`5e-324`）。

Core 層級：整數；絕對值小於 10^16 的整數值浮點數；以及 0.0001 <= |x| 的非整數值浮點數。Full 層級：以上全部。

### 12.6 文字轉數值

`num(s)` 先去除前後空白（Full 層級依 Python `str.strip()` 的 Unicode 空白；Core 層級只去 ASCII 空白），得到 `t`。

- 若 `t` 是可省略的 `-` 後接一個以上 ASCII 數字，結果是該整數，精確無誤（`"007"` 是 7）。前導 `-` 超過一個則是錯誤（`"--5"`）。
- Full 層級，其他情況：依 Python `float()` 的文法讀 `t`：可省略的正負號；數字加可省略的小數部分，或只有小數部分（`".5"`、`"5."`）；可省略的指數（`"1e3"`、`"1E-2"`）；數字之間的單一底線（`"1_000"`）；或不分大小寫、可帶正負號的 `inf`、`infinity`、`nan`。結果是最接近的浮點數；超出範圍的量值成為 `inf`（`"1e400"`）或零。
- Core 層級，其他情況：可省略的 `-`、數字、`.`、數字，得最接近的浮點數。
- 其他都是 `num() cannot convert R`（11.6 節）。

因此 `num("+5")` 與 `num("1_000")` 是浮點數，`num("5")` 是整數；兩者印出來一樣。由實作定義的是：是否接受非 ASCII 的十進位數字（tree 與 vm 接受 `"٣"` 與全形數字；c 拒絕）。超過 4,300 位數的字串是錯誤（14.2 節）。

## 13 字串與文字

### 13.1 碼位

字串是 Unicode 碼位序列。`len`、索引與順序比較都以碼位計，所以 `len("😀")` 是 1，組合用重音符號自成一個碼位。字串原樣送到輸出。

### 13.2 串接與比較

`+` 串接兩個字串。字串在碼位相同時相等（5.2 節），並逐碼位比較順序（5.3 節）。字串永遠不等於數值，兩者之間除了 `str()` 與 `num()` 之外沒有轉換。

### 13.3 值的文字

| 值 | 文字 |
| --- | --- |
| `nil`、`true`、`false` | `nil`、`true`、`false` |
| 數值 | 12.5 節 |
| 字串 | 字串本身，不加引號 |
| 列表 | `[` + 各元素的文字以 `, ` 分隔 + `]`；裡面的字串不加引號：`[1, a b, , nil, [2, []]]` |
| 函式 | `<fn name>`、`<fn <anonymous>>`、`<builtin name>`（Full 層級） |

## 14 限制

### 14.1 呼叫深度

同時進行中的使用者函式呼叫最多 400 個；最外層不算呼叫，標準函式也不計入。會成為第 401 個的那次呼叫是可捕捉的執行期錯誤 `stack overflow (max call depth 400)`，回報在它的 `(`。Core 層級：至少 400，超過實作上限時必須是可捕捉的執行期錯誤。Full 層級：恰好 400（提案 P8 會把 400 改為下限）。

### 14.2 整數文字

整數轉文字最多到 4,300 位十進位數字（正負號不計）。轉換更長的整數是致命錯誤（舊有行為，P5）。`num()` 最多讀 4,300 位數字；更長的數字字串是可捕捉的 `num() cannot convert R`。Full 層級要求。實作註記：這是 CPython `sys.get_int_max_str_digits()` 的預設值，C VM 照抄。

### 14.3 巢狀深度

每個實作都必須接受至少 100 層巢狀括號運算式、100 層巢狀區塊、63 層巢狀函式字面值，並能把巢狀 200 層的列表轉成文字。超過自身上限時，實作必須回報語法錯誤或致命錯誤，不得當掉，也不得中止其他執行（Core）。實際上限由實作定義（附錄 B），把包含自己的列表轉成文字的結果亦同（所有參考引擎在最外層都是致命錯誤；在函式內見附錄 B）。

## 15 一致性

### 15.1 層級

| 層級 | 要求 | 不要求 |
| --- | --- | --- |
| **minilang 1.0 Core** | 所有明定規則，12.5、12.6、14.1 節採 Core 版本 | 訊息文字（但接到的執行期錯誤仍必須是字串）、函式的文字、舊有行為、超出 Core 子集的 Python 式數值文字與 `num()` 文法、4,300 位數上限、精確的呼叫深度 |
| **minilang 1.0 Full** | Core 的全部、精確的訊息文字、所有舊有行為，以及各 Full 版本 | 只有實作定義的部分 |

三個參考引擎都以 Full 實作為目標。Core 實作可以用附錄 C 的任何提案取代它所取代的舊有行為。

### 15.2 可觀察的內容

一次執行可觀察的結果是它印出的文字與結束方式（1.3 節）：完成；語法錯誤與其行號、訊息；未捕捉的執行期錯誤或拋出值與其行號、訊息；或致命錯誤。時間、記憶體用量、REPL 中結尾運算式陳述的值、位元組碼，以及致命錯誤回報的措辭，都不屬於一致性的觀察範圍。

### 15.3 命令列約定

透過命令列測試的實作以 `ENGINE FILE` 執行：

- 以 UTF-8 讀 FILE，並以 UTF-8 把每行 `print` 寫到標準輸出；
- 程式完成時結束碼為 0；
- 未捕捉的語法或執行期錯誤：在標準錯誤寫出 `error: [line N] MESSAGE` 並換行，結束碼為 1；
- 致命錯誤：結束碼為 1，寫出由實作定義、且不以 `error: [line` 開頭的回報；
- 其他結束碼代表實作本身失敗。

實作註記：tree 與 vm 的命令列以系統地區設定的編碼寫標準輸出，所以在地區設定不是 UTF-8 的系統上需要 `PYTHONIOENCODING=utf-8`；執行器會設定它（見說明）。

### 15.4 一致性測試

[tests/](tests/) 中第 2 到 14 節各有一個目錄；每個測試是一支程式，預期輸出與結束方式寫在檔尾的註解區塊，並標明它檢查的節。`conformance.py` 可在任何引擎上執行並逐節回報；測試格式與執行器見[說明](README.zh-TW.md)。測試有層級（`core` 或 `full`）與狀態（`specified`、帶提案編號的 `legacy`，或帶允許範圍與各參考引擎文件化結果的 `impl`）。

## 附錄 D：版本、變更流程與發布關卡

### D.1 兩個版本號

- **語言版本**（本文）：MAJOR.MINOR。MINOR 版本可以增加行為（新標準函式、新語法形式）並改變實作定義的行為，但絕不改變 1.0 在 Full 層級明定結果的程式的結果。MAJOR 版本可以改變明定或舊有行為；採納 P1 到 P6、P8 或 P9 即成為 2.0，被取代的舊有規則在 2.0 刪除。
- **位元組碼格式**（MLBC，記載於 [minilang-c](../minilang-c/README.zh-TW.md)，目前為 1.0）：Python 編譯器與兩個 VM 之間的介面，不屬於語言。既有規則不變：讀取器拒絕其他主版本、較新的次版本或不同的 opcode 數量，重新編號 opcode 是主版本變更。新增一條：改變既有指令行為的語言變更（P2 之於 `LOAD_CHAIN`、P3 之於 `BREAK_OUT`、P1 與 P5 之於 `THROW` 與各運算子），即使沒有新增 opcode 也是 MLBC 主版本變更，因為 MLBC 檔不記錄語言版本，舊檔的意義會悄悄改變。
- **測試**：本目錄的測試是 1.0 的測試；`conformance.py` 會印出它檢查的語言版本。

### D.2 變更怎麼走

1. **提案。** 在附錄 C 新增一項：規則、取代什麼、理由、會改變的測試，以及各引擎的成本。很多提案來自差異測試，D20、D24 與 D30 就是。
2. **規格。** 負責人決定納入某個版本。兩份 SPEC 的文字與測試在同一個提交中修改；新規則的測試在引擎上會失敗（執行器會列出），被取代的測試改成新規則。
3. **引擎。** 逐一修改引擎，直到測試在兩種方式與所有設定下全部通過，且各引擎自己的測試（`test_minilang`、`test_minilang_vm`、`test_minilang_c`、`difftest.py`）仍然通過。前端變更落在 `minilang.py`，再經由它到達另外兩個引擎。
4. **發布。** 在兩份 SPEC 與 `conformance.py` 中提高版本號；說明檔記錄矩陣。

路線圖引用的 TC39 作法要求兩個相容實作才算定案。這裡的三個引擎並非處處獨立：詞法與語法分析器只有一份，vm 重用樹走訪的標準函式、文字與運算子慢速路徑，只有 c 重新實作運算子、數值與文字。第 2、3 節的一致是一個實作和自己一致；第 6、11、12、13 節是兩個；控制流程與作用域是三個。

### D.3 發布關卡

語言或任何引擎的發布都需要：

1. `python3 conformance.py --all-configs` 與 `python3 conformance.py --cli --all-configs` 的結束碼都是 0（每個測試在 Full 層級、每個引擎與設定上都通過）；
2. `--strict` 也通過：每個引擎仍符合附錄 B 的記載，或在同一變更中更新附錄 B；
3. 各引擎自己的測試通過。

測試失敗只能靠修正引擎，或依 D.2 改變規則來解決；絕不能為了配合引擎而修改預期結果。截至本文，關卡**未通過**：c 引擎在 64 層以上的巢狀函式字面值會當掉（`14-limits/nesting-functions-200`），這是要修的 C VM 錯誤，不是要改的規則。
