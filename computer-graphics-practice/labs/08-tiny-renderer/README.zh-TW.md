# 實驗 08 — 期末專題：迷你渲染器展示

[English](README.md) | **繁體中文**

## 目標

用一個自己能執行、能解釋、也能為設計辯護的小型渲染器，完成第一部。題目要求：至少含兩個網格、可移動視角的場景，可移動的攝影機、深度、一個有貼圖的光照材質、陰影或明確記錄的替代方案，以及一個功能開關或除錯檢視。你要交出原始碼、截圖或簡短錄影，以及 1–2 頁的設計說明。

本實驗提供三樣東西：題目與檢查清單、一個在頁面上就能執行並符合要求的參考展示，以及設計說明的大綱。這個展示是已知正確的對照，不是標準答案：你的專題是你自己寫、也能解釋的程式。

```
CPU，一次      網格、貼圖 -> GPU 緩衝區                   著色器原始碼 -> 程式
CPU，每個影格  按鍵與拖曳 -> 攝影機    時間 -> 模型矩陣    滑桿 -> 光源矩陣
階段 1 陰影    從光源發出 6 次繪製  -> 深度貼圖（陰影貼圖）
階段 2 場景    從攝影機發出 6 次繪製 -> MSAA 色彩 + 深度：貼圖、光照、陰影
階段 3 解析    每像素 4 個取樣點 -> 1 個（blitFramebuffer）
階段 4 輸出    縮放後的影像 -> canvas：在線性光中雙線性濾波，sRGB 只編碼一次
```

## 執行

開啟 `../../index.html`，選擇 **08 · 期末展示**。先點一下畫布讓它取得鍵盤焦點，再用 W A S D 移動、Q 與 E 下降與上升、Shift 加速；拖曳可轉動視角。「顯示」可在最終畫面與每個階段的除錯檢視之間切換。讀數會列出目前影格的各個繪製階段、追蹤一個頂點走過每個座標空間，並顯示繪製呼叫、記憶體，以及瀏覽器支援計時查詢時各階段的 GPU 耗時。頁面需要 WebGL 2，但不需要伺服器或網路連線。

## 參考展示對照題目要求

| 要求 | 展示中的做法 | 在 `app.js` 的位置 |
| --- | --- | --- |
| 至少含兩個網格、可移動視角的場景 | 磁磚地面、兩個木箱、球體、柱子與旋轉立方體：四個網格、六個物體 | `MESHES`、`SCENE` |
| 可移動的攝影機 | 飛行攝影機：W A S D、Q／E、Shift，拖曳轉動視角 | `camera`、`cameraAxes`、`updateCamera` |
| 深度 | 兩個階段都做深度測試，另有把視窗深度換回視圖距離的檢視 | `shadowPass`、`scenePass`、`uView == 4` |
| 一個有貼圖的光照材質 | 磁磚與木箱貼圖（`SRGB8_ALPHA8`，含 mipmap），在線性光中以 Lambert 與 Blinn–Phong 計算光照 | `makeTileTexture`、`makeCrateTexture`、`SCENE_FRAGMENT_SHADER` |
| 陰影或明確記錄的替代方案 | 陰影貼圖，搭配 3 × 3 雙線性 PCF 與斜率偏移 | `lightFrame`、`shadowPass`、`shadowFactor` |
| 功能開關或除錯檢視 | 五個開關、七種檢視、渲染比例與陰影貼圖大小 | 畫布下方的控制項 |

## 閱讀實作

`app.js` 依照一個影格需要的順序排列：

1. **設定**每個影格從頁面讀取一次（`readSettings`），讓每個階段看到相同的值。
2. **場景就是資料。** `MESHES` 用 `../common/mesh.js` 建立幾何。`MATERIALS` 存放顏色（sRGB，上傳時解碼）、貼圖名稱、UV 縮放與高光參數。`SCENE` 把網格、材質，以及可隨時間變化的模型矩陣配成一組。新增一個物體只要加一行。
3. **攝影機**由位置、偏航與俯仰組成。`cameraAxes` 把偏航與俯仰換成前方與右方向量，視圖矩陣是 `lookAt(eye, eye + forward, up)`。只有畫布取得焦點時按鍵才有作用，頁面仍能正常捲動。
4. **GPU 資源**在 `setup` 中透過 `../common/webgl.js` 一次建立：四個程式、四個網格、兩張貼圖、陰影貼圖、讀取原始深度的取樣器，以及 GPU 計時器。`sceneTargets` 只在渲染比例或 MSAA 改變時重建場景的渲染目標。
5. **繪製階段。** `shadowPass` 與 `scenePass` 都會畫出每個物體。`webgl.resolve` 平均 MSAA 取樣點。`presentPass` 在線性光中把場景影像濾波成 canvas 大小，並只編碼一次。渲染比例 2× 時，雙線性取樣點正好落在四個紋素中間，所以等於 2 × 2 平均（SSAA）；0.5× 時則是放大。
6. **一個影格。** `buildFrame` 收集各階段需要的資料：設定、矩陣、光源，以及每個物體此刻的模型矩陣。`render` 在 GPU 計時查詢中執行各階段，再填入讀數。`showTrace` 在 CPU 上對旋轉立方體的一個角重做頂點著色器的計算，提供設計說明需要的數字。

這裡每個概念你都見過：法線矩陣與 Blinn–Phong 來自實驗 06；陰影查詢、偏移、渲染目標、MSAA 與線性光解析來自實驗 07；頂點追蹤來自實驗 03。

## 慣例

與 [`../../CONVENTIONS.zh-TW.md`](../../CONVENTIONS.zh-TW.md) 相同：+y 朝上的右手世界、行向量與行優先儲存、NDC +y 朝上、裁切體 −w ≤ z ≤ w 且視窗深度為 (z_ndc + 1) / 2、深度測試保留較小值、逆時針為正面且兩個階段都剔除背面、在線性光中著色且 sRGB 貼圖在濾波前解碼，以及實驗 07 的陰影貼圖查詢方式。追蹤讀數中的像素列從上往下數，與 CPU 實驗相同；WebGL 的視窗 y 則從下往上數。

## 你的專題

選擇一條路線，並在設計說明中寫明：

- **擴充這個展示。** 保留它的結構，完成下列練習中至少三題；其中至少一題要新增或修改一個繪製階段或渲染目標。
- **從自己的實驗程式出發。** 以你的實驗 06 或 07 程式為起點，達成同樣的要求。這個展示只用來比較畫面與耗時。

不論哪條路線，交出的每一行程式你都要能逐行解釋，而且要像各個實驗一樣，不需建置步驟就能從網頁執行。

### 交付項目

1. **原始碼**，放在你自己的資料夾，開啟一個 HTML 頁面即可執行。
2. **截圖或 30–90 秒的螢幕錄影：** 最終畫面、你加入的每個除錯檢視、一個瑕疵修正前後的對照，以及一次相同放大倍率下的畫質比較。
3. **1–2 頁的設計說明**，依照下列大綱撰寫。

### 設計說明大綱

1. **渲染流程圖。** 每個繪製階段的輸入、目標（大小、格式、取樣點數）、狀態與著色器。標出哪些階段可程式化、哪些是固定功能。
2. **慣例。** 座標系手性、矩陣儲存與相乘順序、NDC 的 y、深度範圍與測試、正面與剔除，以及色彩在哪裡解碼與編碼。凡與 `CONVENTIONS.zh-TW.md` 不同之處都要註明。
3. **追蹤一個頂點。** 把一個頂點從物件空間經過世界、視圖、裁切、NDC 與視窗座標，追到它落在的像素以及該像素顯示的值，並附上數字。若有陰影，也加上它在陰影貼圖中的座標。
4. **一個你診斷過的錯誤。** 症狀、最初的假設、證實或推翻假設的除錯檢視或量測，以及修正方式。
5. **一項畫質／效能取捨。** 兩個選項、量測方式（GPU 計時查詢，或控制變因的影格時間比較）、數字，以及你的選擇。
6. **限制與下一步。** 你的渲染器還做不到什麼，以及你會先改哪裡。

## 練習

可選的延伸題，每題都註明它延伸自哪個實驗。

- **A — 聚光燈：** 把平行光換成聚光燈：位置、光錐、陰影階段使用 `perspective()`、查詢時除以 w，以及距離衰減（實驗 07 的 E 題、實驗 06 的 A 題）。
- **B — 法線貼圖：** 為木箱加上切線屬性，在 canvas 上畫一張法線貼圖，並在切線空間中擾動法線（實驗 06 的 G 題）。
- **C — 更好的材質：** 加入 Schlick Fresnel 與能量正規化的高光（實驗 06 的 B、C 題），或實作金屬度–粗糙度模型，預習第二部的 E3 階段。
- **D — 視錐剔除：** 為每個物體加上包圍球，略過位於攝影機視錐外的繪製，並顯示略過的數量。在 200 個物體下量測 JavaScript 與 GPU 耗時。
- **E — 實例化繪製：** 用 `drawElementsInstanced` 與每個實例各自的模型矩陣畫出 500 個木箱，並和 500 次個別繪製比較 JavaScript 耗時與 GPU 耗時。
- **F — 穩定的陰影：** 讓光源方框貼合攝影機的視野並對齊到整數個紋素，或把它分成兩個串接區間（實驗 07 的 C 題）。
- **G — HDR 與色調映射：** 繪製到 `RGBA16F` 目標（需要 `EXT_color_buffer_float` 擴充），把光源強度調到大於 1，並在輸出階段、sRGB 編碼之前做色調映射。和單純截斷比較。
- **H — 點選物體：** 把物體 ID 繪製到整數格式的目標，用 `readPixels` 讀取滑鼠下的像素，並顯示該物體的名稱、模型矩陣與材質。為什麼點擊時讀回可以接受，每個影格都讀回卻不行？

## 自我檢視

交出前確認：

- 同學能在一分鐘內打開頁面、移動攝影機並改變一個控制項，不必閱讀你的原始碼。
- 流程圖中的每個繪製階段、目標與著色器都存在於程式中，程式中也沒有流程圖缺少的部分。
- 每個除錯檢視都說明它顯示什麼，而且至少有一個幫你找到過錯誤。
- `CONVENTIONS.zh-TW.md` 結尾的移植檢查清單，對你的場景全部通過。
- 你的取捨主張建立在別人用你的設定也能重做的量測上。
- 瀏覽器主控台沒有錯誤，開發期間 `gl.getError()` 也沒有回報錯誤。

## 檢核問題

在實驗筆記中回答：

1. 用追蹤讀數，把旋轉立方體的角從物件空間追到 canvas 上的像素，並追進陰影貼圖。哪些步驟是矩陣乘法？哪一步是除法？GPU 處理同一個頂點時，哪些步驟由固定功能硬體完成？
2. 列出展示中的各個繪製階段，以及它們的目標、大小與取樣點數，並說明之後由誰讀取每個目標。若 GPU 預算減半，你會先刪掉或縮小哪個階段？畫面會失去什麼？
3. 要找出下列問題時，你會先打開哪個除錯檢視：(a) 錯誤的法線矩陣、(b) 上下顛倒上傳的貼圖、(c) 陰影痤瘡、(d) 設得太近的近裁切面？逐一刻意弄壞，驗證你的答案。
4. 在渲染比例 0.5×、1×、2× 與 MSAA 開關的各種組合中，哪一種在你的 GPU 上每毫秒換到的畫質最好？附上量測結果。
5. 說出一項你的渲染器和這個展示不同的做法，並說明理由。
