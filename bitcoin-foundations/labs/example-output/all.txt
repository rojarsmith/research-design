== secp256k1：私鑰是一個隨機數 d，公鑰是點 d*G ==
私鑰 d   = 2b88ef240c48b772e28d4c24801eae623fced78f7aef212a139953c256ca22ef
公鑰 d*G = (4eda8dc9c60ce7caa3dc2b7d2501ccbf6f94379e47c24ec5ccd6b7b3dbdf17b2,
            8a37c209a5e6b0f897d1a7541c7d6c39a700c80fd679789d48620242551b327e)
在曲線上：True；倍加法用了 379 次點運算，花 5.0 ms
可能的私鑰數量 n ≈ 1.158e+77（約 2^256）

反過來：只給公鑰，暴力猜私鑰。先用一個很小的私鑰示範可以猜到：
  試了 54321 次找到 d = 54321，花 0.78 秒，約每秒 70,039 次
  真的 256 位元私鑰：最好的已知通用演算法也要約 2^128 步，
  以這個速度約 1.5e+26 年；就算快一兆倍也還要 1.5e+14 年。

== 數位簽章：證明「我知道私鑰」，卻不把私鑰交出去 ==
訊息：Alice 付 Bob 0.1 BTC
簽章 (R.x, s) = (895caec5a3fd543deab2849bf453b516757facbfd4f90af23fecc0bb05fe39b8, aeb78e0b679cf6c4a7298c1dd6afaf6ef65cd8f1f52af08e3b03c1a4d63e8e49)
用公鑰驗證原訊息：True
把金額改成 1.0 BTC 再驗：False
驗證式：s*G == R + e*Q。因為 s = k + e*d，兩邊乘 G 就相等；不知道 d 就湊不出 s。

反例：兩筆簽章用了同一個 nonce k，會發生什麼？
  s1 - s2 = (e1 - e2) * d  =>  d = (s1 - s2)/(e1 - e2)
  算出的私鑰與真的私鑰相同：True
  曲線本身沒被破解，是使用方式錯了：nonce 重複就等於公開私鑰。

  區塊 1: 前=282ba328eb7f3b6b 內容=A 付 B 10   雜湊=cc5385b61cad12b8

  區塊 1 新雜湊=75cecae63e901eb7，區塊 2 記的前一塊=cc5385b61cad12b8，相同嗎？False
