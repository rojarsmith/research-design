# LVGL Pro 分析：如何讓使用者願意付費

查核日期：2026 年 11 月 19 日。資料來自 LVGL 官方頁面（[定價](https://lvgl.io/pro/pricing)、[授權公告](https://lvgl.io/blog/announcement-lvgl-pro-licensing)、[產品頁](https://lvgl.io/pro)、[lvgl_pro README](https://github.com/lvgl/lvgl_pro)、[文件](https://lvgl.io/docs/pro/editor/overview)）。官方各頁面的方案結構互相不一致，下文以定價頁為準，並標出差異。

## 一句話結論

**不要和 LVGL Pro 比「誰的 UI 編輯器比較好」。** LVGL Pro 是 LVGL 原廠出品，對象是會寫 XML 與 C 的 UI 工程師，最終輸出 UI 程式碼。EHS 要收費，價值必須落在 LVGL Pro 刻意不做的地方：**讓整台連網裝置跑起來**，包含現場通訊、應用邏輯、多執行緒、上雲、OTA、整機模擬，以及給客戶看的 Demo。最好在格式上與 LVGL Pro 互通，讓使用者不必二選一。

### 官方頁面**沒有列出**的能力

官方頁面沒有列出下列能力，不代表 LVGL Pro 永遠不做：

- 現場通訊協定（Modbus、CAN、UART 指令）與外部裝置的標籤模型
- 視覺化應用邏輯：它的邏輯只有綁定與事件，沒有流程圖
- 網路與雲端：MQTT、HTTP、裝置憑證
- OTA
- RTOS 與多執行緒模型
- 板級 BSP、一鍵建置與燒錄
- 模擬外部裝置（例如模擬一台 Modbus 從站）
- 可寄給終端客戶、免安裝的單檔 Demo
- 給非程式背景者用的 No Code 流程

## 讓使用者願意付費的五個價值

付費的理由要能換算成**時間、風險或營收**。工程師對「再一個 UI 編輯器」沒有付費意願，但會為下列結果付錢：

### 1. 從空白到「會動的連網樣機」只要一天，而不是三週

LVGL Pro 交付 UI 程式碼，剩下的 Modbus 輪詢、資料轉換、錯誤處理、上雲、Task 切分都要自己寫。EHS 交付的是**整台會動的裝置**。

這個價值可以量測：選一個標準情境（例如 EV 充電樁：顯示電壓與電流、Modbus 讀電表、MQTT 回報、OTA 更新），比較「LVGL Pro 加手寫」和「EHS」的完成時數。這個數字就是銷售話術的核心。

### 2. 把最難的 bug 在設計期擋掉

嵌入式產品最貴的 bug 是並行問題：LVGL 被兩個執行緒同時呼叫、通訊逾時卡住畫面、堆疊溢位。這類問題很難重現。EHS 從三個層次處理：

- 在結構上禁止非 UI Task 碰 LVGL。
- 在設計期偵測多個寫入者，並估算堆疊用量。
- 在模擬器確定性重播。

這是在賣「降低風險」，比賣功能好收錢。

### 3. 業務與客戶溝通的工具

單檔 HTML Demo 可以讓**業務**、**終端客戶**、**決策者**都看到成品，不需要 GitHub 帳號或任何安裝。B2B 裝置案常常卡在「客戶看不到東西就不下單」，Demo 直接縮短銷售週期。

這個功能的付費者往往不是工程師，而是專案經理或業務主管，**付費者和 LVGL Pro 不同**。

### 4. 量產之後的維護與法規

CRA 從 2027-12-11 起全面適用：有網路功能的產品需要 SBOM、弱點處理與安全更新機制。工具若能：

- 一鍵輸出 SBOM，
- 內建 OTA 與回滾，
- 留存版本紀錄，

就能把一次性的工具費轉成**持續性**的訂閱理由。LVGL Pro 的範圍止於 UI 程式碼。

### 5. 不必為了 UI 而雇 UI 工程師

小型 OEM 與系統整合商常常沒有專職 UI 工程師，用 LVGL Pro 要先學 XML、Subject 與 C 整合。EHS 的 No Code 與 Low Code 雙模式，讓應用工程師也能交付，**省下的是一個職缺**。

## 競爭策略：互補優先，避免正面衝突

| 策略 | 做法 | 理由 |
| --- | --- | --- |
| 格式互通 | 評估匯入與匯出 LVGL XML（元件與畫面），讓 LVGL Pro 使用者把 UI 帶進 EHS，加上 IoT 層 | 使用者不必二選一；LVGL Pro 的成長也會帶進潛在客戶。需先確認 XML 規格與執行期載入器的授權（XML 文件放在開源文件區，但執行期載入要洽詢）。（2026-11 查證更正：LVGL XML 授權禁止第三方 UI 編輯器與程式碼產生器未經書面許可讀寫這個格式；LVGL 9.5 起移除 XML 引擎，執行期載入改為付費授權，見 [18 號研究](18-mpu-runtime.zh-TW.md)） |
| 不碰原廠強項 | 不追逐所有 LVGL 新 Widget 的編輯體驗；UI 層保持「夠用加可匯入」 | 原廠永遠比較快 |
| 定價錯位 | 席位價低於 LVGL Developer（US$3,990）；量產授權遠低於 US$20,000／產品；提供 Starter 方案 | 中小型 OEM 對 US$20,000 很敏感 |
| 以結果銷售 | 每個垂直市場提供可運作的範本專案（充電樁、洗衣機、空壓機、醫療泵浦面板）加上模擬裝置 | 買的是「完成的 80%」，而不是工具 |
| 晶片商合作 | 學 LVGL 與 Renesas 的模式，找一家晶片商贊助免費授權（可考慮 ESP32-S3 或 Nuvoton 等在亞洲有量的廠商） | 換取通路與曝光 |

### 建議的定價結構（待訪談驗證）

| 方案 | 價格（假設） | 內容 |
| --- | --- | --- |
| Community | 免費 | 非商業；模擬器與 Demo 匯出加浮水印；只支援評估板 |
| Pro | US$790 至 1,490／席／年 | 全功能 VS Code 擴充與桌面版；所有目標板；CLI |
| Product | US$4,000 至 8,000／產品（3 年） | 不限席位；含 OTA 串接與 SBOM 輸出；量產用 |
| OEM 與通路 | 洽詢 | 模組商（例如 EDT）白標內建，按出貨模組或年費計 |
| 服務 | 按案計 | 範本客製、連接器開發、導入訓練 |

LVGL Pro 免費提供給 Renesas 客戶，代表「工具免費、晶片商付錢」在這個市場已被接受。EDT 現行的「軟體免費、賣模組」是同一邏輯，所以分拆後 **OEM 與通路授權可能比席位收入更重要**。

## 需要驗證的問題

1. 目標客戶在 LVGL Pro 與 EHS 之間，實際比較的是什麼？是價格、No Code，還是 IoT？要靠訪談回答，不能靠推論。
2. LVGL XML 的匯入與匯出是否有授權限制？（已查證：有，須書面許可，見 [18 號研究](18-mpu-runtime.zh-TW.md)）LVGL Pro v2.0 是否已加入資料來源或邏輯功能？下載頁仍是 1.2.1，需要追蹤 [releases](https://github.com/lvgl/lvgl_pro/releases)。
3. 「一天完成連網樣機」的時數對比要實際做一次，留下錄影與紀錄，作為行銷證據。
