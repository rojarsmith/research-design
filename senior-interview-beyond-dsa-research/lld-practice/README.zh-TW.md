# LLD/OOD 與 machine coding 練習包（VS Code、Windows 11）

這個練習包把[研究報告](../README.zh-TW.md)第 5 節（LLD/OOD）的建議做成可以照著走的練習：第 5.2 節的框架、第 5.3 節的評分重點、第 5.6 節的練習方式。

- **4 題原創題目**：每題涵蓋第 5.4 節對照表的不同考點，其中一題是並行。題目、測試、參考設計都是為這個專案寫的，沒有從任何題庫複製。每題有核心需求，加上 2 到 3 個一次揭曉一個的「如果……」變體，每個變體都有自己的測試。
- **`ood` 練習工具**：用 C++ 寫成。先寫設計筆記才能寫程式，替設計、核心和每個變體計時，一次揭曉一個變體。**每做完一個變體，就算出你改了多少既有的類別、函式和程式碼行。**第 5.6 節說的就是這個訊號：改動範圍小，代表職責劃分得好。
- **只需要裝三樣東西**：VS Code、C/C++ 擴充、WinLibs GCC，跟 [cpp-practice](../../coding-interview-practice-research/cpp-practice/README.zh-TW.md) 和 [ai-round-practice](../ai-round-practice/README.zh-TW.md) 一樣。有 Git 的話，行數會用 `git diff` 算；沒有也能練。

| --- | --- | --- | --- |

| 2 | **照面試的時間** | 第 5.1、5.2 節：LLD 約 35 分鐘；Flipkart 一類的 machine coding 約 90 分鐘 | 兩種模式。`design`：設計 20 分、核心 15 分，共 35 分。`machine`：設計 15 分、核心 75 分，共 90 分。每個變體各 10 或 15 分。超時會提醒 |

## 2. 安裝

1. 安裝 [VS Code](https://code.visualstudio.com/)。
2. 用 Windows 11 內建的 winget 安裝 WinLibs GCC。已經為 cpp-practice 或 ai-round-practice 裝過的話就跳過這步。

   ```bash
   winget install --id BrechtSanders.WinLibs.POSIX.UCRT --exact
   ```

3. **重新開啟 VS Code**，讓新的 PATH 生效。接著用「檔案 → 開啟資料夾」打開 `lld-practice` 這個資料夾（不是整個 repo）。
4. VS Code 會提示安裝建議的擴充 **C/C++**（`ms-vscode.cpptools`），裝這一個就好。

第一次執行任何 `ood:` 工作時，會自動建置 `build/ood.exe`，約 10 秒。

## 3. 一次練習的流程

主視窗（`lld-practice`）只用來開始練習，題目在新視窗裡做。

| 步驟 | VS Code | 終端機 |
| --- | --- | --- |
| 1. 開始 | 主視窗執行工作「ood: 開始新的練習」，選題目和模式。工具會建立 `work/<題目>-<時間>/`，並用新視窗打開 | `.\build\ood.exe start parking-garage --mode design` |
| 2. 設計 | 讀 `TASK.md`，在 `DESIGN.md` 寫五個欄位。邊寫邊講，像面試官在聽 | |
| 3. 設計完成 | 工作「ood: 設計完成，開始寫程式」 | `ood design` |
| 4. 實作與測試 | 在 `src/` 寫程式，**Ctrl+Shift+B** 跑測試 | `ood test` |
| 5. 看目前改了多少 | 工作「ood: 目前改了多少」 | `ood diff` |
| 6. 下一個變體 | 工作「ood: 下一個變體」：先結算這一段的改動，再揭曉下一個。時間到了，用「跳過並揭曉下一個變體」 | `ood next`、`ood next --skip` |
| 7. 預測 | 在 `DESIGN.md` 新增的「變體 N 預測」寫下要改哪些類別，才能跑測試 | |
| 8. 看時間 | 工作「ood: 狀態」 | `ood status` |
| 9. 執行示範程式 | 工作「ood: 執行程式」（`app/main.cpp`，machine 模式要寫） | `ood run` |
| 10. 結束 | 工作「ood: 結束並複盤」執行兩次：第一次停錶並產生 `REVIEW.md`；填完四欄後再執行一次，才記錄並顯示複盤要點 | `ood done` |

在練習資料夾的終端機裡，`ood` 指的是主視窗的 `build/ood.exe`。直接用工作最方便，因為工作裡已經寫好完整路徑。

**design 模式的 35 分鐘到了怎麼辦。** 真正的面試到這裡就結束，`ood status` 會提醒你記下卡在哪一步。之後可以不計入面試時間，把核心寫到測試全過，再做變體；變體的計時是另外算的。

**要錄下來。** 用 Windows 內建的「剪取工具」錄螢幕，或 Xbox Game Bar（Win+G）。複盤時對照第 5.3 節的五個評估面向。

## 4. 四題

| 題目 | 第 5.4 節的考點 | 核心 | 變體（依序揭曉） |
| --- | --- | --- | --- |
| `parking-garage` 多層停車場 | 可替換的演算法或計費規則（Strategy） | 依車種分配車位、依時間收費 | 1 多種計費方案；2 換一種分配車位的規則；3 電動車充電 |
| `expense-approval` 費用報銷審核流程 | 狀態機 | 送出、撤回、核准、退回、付款，含權限和歷史 | 1 大額要財務再審；2 主管休假時的代理人；3 狀態改變時通知相關的人 |
| `auction-house` 線上拍賣與通知 | 事件通知（Observer） | 出價規則、關注者、結束時通知 | 1 使用者選擇通知方式（全部、重要、摘要）；2 防止最後一秒出價；3 直接購買 |
| `seat-holds` 演唱會座位保留 | 預約與並行 | 多執行緒同時保留、確認、釋放，保留會過期 | 1 每位客人的座位上限；2 每個座位的候補名單 |

`parking-garage` 的三個變體就是第 5.6 節舉的例子（電動車充電、多種計費方式），只把「預約」換成分配規則，因為預約和 `seat-holds` 重複。

題目用英文寫，跟正式面試一樣；工具的訊息和複盤要點用中文。每題的測試數：核心 7 到 11 個，每個變體 4 到 7 個。

**放進 12 週計畫**（研究報告第 7.2 節的「LLD/OOD」欄；目標公司有考 LLD 才做）：

| 週 | 第 7.2 節 | 練習包 |
| --- | --- | --- |
| 1–2 | 問招募人員要不要考 | 不考就到此為止；第 5.6 節說只要讀一次框架、做 1 到 2 題 |
| 3–4 | 讀框架；做停車場、LRU 快取 | `parking-garage`，`design` 模式 |
| 5–6 | 電梯、電影訂票（含並行） | `expense-approval`（狀態機，和電梯同一類）、`seat-holds`（訂票加並行） |
| 7–8 | 1 到 2 題，加上擴充追問 | `auction-house`；目標公司是 machine coding 的話，挑一題重做 `machine` 模式 |
| 9–12 | 有考才維持每週 1 題 | 重做改動最大的那題，或照第 6 節自己加題目 |

同一題重做時，變體你已經知道了。重做只拿來練別的東西：換 `machine` 模式、換一種設計再量一次改動、或專門練「邊做邊講」。

## 5. 怎麼讀改動數字

每個變體結束時，`ood` 會印出類似這樣的結果：

```
變體 1 的改動（和揭曉這個變體時的程式相比，只算 src/）：
  既有的類別改了 2 個：Rules、Transition
  既有的函式改了 2 個：Rules::Rules、Rules::find
  新增的類別 0 個；新增的函式 1 個：needsFinanceReview
  改在既有類別和函式裡的程式碼：+6 −1 行；寫在新類別和新函式裡的：+1 行
  檔案：改了 2 個、新增 0 個、刪除 0 個
  全部行數：+8 −1（git diff）
  你的預測：Rules 的轉移表多兩行，其他不動
```

- **最重要的是「既有」的數字**：改到幾個已經存在的類別和函式、在它們裡面改了幾行。擴充本來就要新增程式，新增的類別和函式不是壞事；開放封閉原則說的是盡量不改舊的。
- **一個數字不夠，要一起看。** 在結構體加一個欄位也算改了一個類別；一個什麼都包的大類別，改再多也只算「1 個類別」。所以要同時看既有函式和既有程式碼行。
- **不是每個變體都會拉開差距。** 規則本來就集中在一個地方時，好的設計和差的設計都只改一處。只有跨越職責的變動才會分出高下。每題的複盤要點都附上兩套參考設計的實測數字，說明哪個變體拉開了差距、為什麼。
- **只算 `src/`**。`tests/` 和 `app/` 不算。空行、註解、只有括號的行，不算進各個類別和函式的行數，但算進全部行數。
- **全部行數**：有 Git 時用 `git diff --minimal`，沒有 Git 時用工具自己的快照比對；兩者在驗證時結果相同。類別和函式的歸屬，永遠由工具自己分析程式碼得到，因為 Git 不知道類別。
- **這是啟發式的分析，不是編譯器。** 它認得類別、結構體、列舉、類別內的方法、`X::f` 形式的類別外定義、建構子的初始化列表和樣板。巨集產生的程式碼、奇特的寫法可能歸錯類別。看到奇怪的歸屬時，`ood diff` 會逐項列出每個類別和函式的行數。

## 6. 專案結構

```
lld-practice/
├─ .vscode/                  主視窗的工作：開始練習、題目清單；隱藏 problems/ 和 work/
├─ tools/ood.cpp             練習工具（第一次執行工作時自動編譯）
├─ common/
│  ├─ check.hpp              測試框架：TEST、THREAD_TEST、缺少方法的提示、死結監視、固定的亂數
│  └─ test_main.cpp          測試的進入點
├─ problems/
│  ├─ catalog.tsv            題目清單
│  └─ <題目>/
│     ├─ statement.md        題目與核心需求（開始時放進 TASK.md）
│     ├─ start/              空白骨架：src/ 的公開介面、app/main.cpp、tests/phase1_tests.cpp
│     ├─ variants/           變體的題目與測試（揭曉時才複製）
│     └─ debrief.zh-TW.md    複盤要點（ood done 之後才複製）
├─ work/                     你的練習資料夾（自動建立，不進版本控制）
│  └─ parking-garage-20261120-203000/
│     ├─ TASK.md、DESIGN.md、REVIEW.md
│     ├─ src/、app/、tests/
│     ├─ .ood/               計時狀態與每個變體開始時的快照
│     └─ .vscode/            這次練習的工作與除錯設定
├─ progress/sessions.tsv     每次練習的紀錄（自動建立，不進版本控制）
└─ build/                    建置產物（隨時可以整個刪掉）
```

每次練習都是獨立的資料夾，也是獨立的 git repo：骨架、核心結束、每個變體結束時各提交一次，並打上 `ood-p1`、`ood-p2`…… 的標籤，所以 `git diff ood-p2 ood-p3` 就是變體 2 改的東西。練習資料夾預設在 `work/`（不進版本控制），`ood start ... --out <資料夾>` 可以放到別的地方。

**自己加題目。** 照 `problems/<題目>/` 的結構建一個資料夾，在 `catalog.tsv` 加一行（最後一欄是公開介面的標頭檔名）。變體的測試如果要呼叫新方法，照現有題目的寫法用 `if constexpr (requires { ... })` 包起來，還沒寫的方法就會變成清楚的失敗訊息，而不是編譯錯誤。

## 7. 已驗證

在 Windows 11 上用 WinLibs g++ 16.2.0 驗證過以下各點。參考設計沒有放進專案。

- **空白骨架一定會失敗。** 四題的骨架對每個階段的每個測試都失敗：parking-garage 0/22、expense-approval 0/30、auction-house 0/25、seat-holds 0/19。變體要求的新方法還不存在時，測試照樣能編譯，並列出缺少的方法簽章。
- **每題寫了兩套參考設計，都通過全部測試**：一套照職責劃分、容易擴充；一套刻意僵硬（規則散在各個方法裡、用字串判斷型別、過期的判斷各寫各的），但核心一樣全部通過。每一版拿去跑下一個變體的新測試，都全部失敗，所以每個變體的測試真的要求新的行為。
- **改動數字。** 格式是「既有類別 / 既有函式 / 改在既有類別和函式裡的程式碼行」：

  | 題目 | 變體 | 容易擴充的設計 | 刻意僵硬的設計 |
  | --- | --- | --- | --- |
  | parking-garage | 1 計費方案 | 1 / 0 / +1 −0 | 1 / 1 / +12 −0 |
  | | 2 分配規則 | 1 / 0 / +1 −0 | 1 / 1 / +13 −6 |
  | | 3 電動車充電 | 4 / 3 / +11 −4 | 3 / 5 / +39 −26 |
  | expense-approval | 1 大額財務審核 | 2 / 2 / +6 −1 | 2 / 4 / +26 −11 |
  | | 2 主管代理 | 1 / 2 / +17 −7 | 2 / 3 / +19 −6 |
  | | 3 通知 | 2 / 2 / +6 −0 | 1 / 5 / +17 −0 |
  | auction-house | 1 通知偏好 | 2 / 1 / +15 −1 | 1 / 2 / +12 −7 |
  | | 2 防止最後一秒出價 | 3 / 2 / +6 −1 | 1 / 1 / +5 −0 |
  | | 3 直接購買 | 2 / 0 / +5 −0 | 2 / 1 / +5 −13 |
  | seat-holds | 1 每位客人的上限 | 1 / 1 / +4 −0 | 1 / 1 / +8 −0 |
  | | 2 候補名單 | 1 / 1 / +7 −1 | 2 / 5 / +18 −2 |

  - 11 個變體裡，僵硬的設計有 9 個改到更多既有函式（1 個相同、1 個較少），有 10 個在既有程式裡改了更多行。
  - 例外是 auction-house 的變體 2：兩套設計的出價規則都集中在一個函式裡，所以兩邊都只改一處，容易擴充的那一套還多改了事件種類。
  - 「既有類別」這一欄沒有穩定地分出兩者，原因見第 5 節。
  - 每題的複盤要點都解釋了各個變體的差距從哪裡來。
- **行數的兩種算法一致。**
  - 容易擴充的設計用 git 跑（`git diff --minimal`），每個變體的總行數都等於事先用快照比對算出的數字。
  - 僵硬的設計用 `OOD_NO_GIT` 跑快照比對。
  - 另外有一次把 git 從 PATH 拿掉的完整練習：工具沒有建立 `.git`，改用快照比對。
- **並行測試可靠。**
  - 兩套正確的 seat-holds 參考設計，5 個多執行緒測試各跑 20 次，都是 20 次全部通過（每次 0.6 到 3.8 秒）。
  - 三種刻意寫錯的版本各跑 10 次，每次都被抓到：完全不上鎖，10 次都是三個核心多執行緒測試全部失敗；每個座位一把鎖、照請求的順序拿，10 次都在 20 秒時被判定為死結；上限檢查和保留分在兩段鎖裡，10 次都在 100 輪中的前 4 輪內失敗。
- **完整流程跑過**，每題兩次：一次 `design` 模式加 git，一次 `machine` 模式不用 git，並用 `OOD_MINUTE=1` 縮短時間。流程是：
  1. 開始；設計筆記沒寫完時拒絕測試，欄位不齊時拒絕 `ood design` 並列出缺哪幾欄。
  2. 骨架測試全失敗，核心通過，`ood next` 結算改動並揭曉變體。
  3. 沒寫預測時拒絕測試；上一版對新測試全失敗，換上新版後通過，改動報告和預測並列。
  4. 執行示範程式、看狀態與超時提醒。
  5. 結束時 `REVIEW.md` 欄位不齊就拒絕記錄，填完後記錄並顯示複盤要點。

  沒有 git 的那一次另外跑了 `ood diff`（逐項清單）和 `ood debug`（建出 `tests-debug.exe`）。
- **沒有驗證的部分：**
  - VS Code 的工作和 F5 除錯沒有在 VS Code 裡實際操作。工具從不打開視窗，所有工作呼叫的指令都在終端機跑過。
  - Linux 和 macOS 沒有測試。
  - 學習者自己的設計沒有驗證過。改動分析是啟發式的，只確認過它在這 8 套參考設計上列出的類別和函式，和實際修改的地方一致。

## 8. 疑難排解

| 症狀 | 處理 |
| --- | --- |
| 找不到 `g++` | 裝完 WinLibs 後要重開 VS Code。在終端機執行 `where g++` 確認。 |
| 新視窗沒有自動打開 | `code` 不在 PATH 上。手動用「檔案 → 開新視窗」，再打開 `ood start` 印出的資料夾。 |
| 測試說「missing from your facade」 | 變體要求新增的公開方法還沒寫，或簽章不同。訊息裡有完整的簽章。 |
| 顯示 `TIMEOUT ... still running after 20 s` | 多執行緒測試卡住了，通常是死結：兩把鎖用不同順序拿，或等待沒有人喚醒。 |
| 顯示 `crashed with exit code -1073741819` | 存取違規。多執行緒測試裡，常常是沒有上鎖就修改 `std::map` 或 `std::vector`。 |
| 改動數字把某行算到奇怪的類別 | 執行 `ood diff` 看逐項清單。分析是啟發式的，見第 5 節。 |
| 中文變亂碼 | 在終端機先執行 `chcp 65001`。 |
| 改了 `tools/ood.cpp` | 主視窗執行工作「ood: 重新建置工具」。 |
| 只想測試 `ood` 本身 | 在 `ood start` 之前設定環境變數 `OOD_MINUTE=1`，一分鐘就只有 1 秒（只用來測試工具，不要拿來練習）；`OOD_NO_GIT=1` 強制用快照比對。 |
| 不想要某次練習了 | 直接刪掉 `work/` 底下那個資料夾。紀錄在 `progress/sessions.tsv`，要刪也可以直接刪。 |
| Linux 或 macOS | `ood` 和測試框架的程式碼有處理這兩個平台，但沒有實際測試過。 |
